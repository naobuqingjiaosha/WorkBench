## 三·补二：B3-8 内容抽取与向量化（**已落地**，2026-10-02）

| 设置键 | 默认 | 可选 | 依据（一句话） |
|---|---|---|---|
| `kb.dedup` | `prefer_docx`（优先 docx；同文号只留一份） | `all` / `by_name` / `by_hash` | 「同一份制度在检索里出现 3 次」是最直接的质量损伤；**文号**是用户自己的行政标识，比文件名/内容哈希都稳 |

**实测（隔离实例 + `.tmp` 自造假制度目录，10 个文件覆盖 docx/同文号两版/法规/参考制度/非制度/坏 docx/空文件/扫描件 pdf）**：67 项断言全绿。换口径来回切（版本 `all`↔`final_only`、范围 `mark`↔`exclude`、去重 `all`/`by_hash`/`prefer_docx`）后**没有重复行**、按新口径不该入库的行会被清理、片段数与向量数逐次对得上；**600 文件批量抽取 6.4 秒**（进度轮询 p95 10ms、max 29ms —— 抽取期间接口不卡），30 个坏文件全部隔离成 `fail` 且整批跑完；抽取前后来源目录快照（递归清单+大小+mtime）**完全一致**。

**踩到并修掉的 5 个坑**（都写进了代码注释）：
1. **去重的判定必须能覆盖前一步的结论**：用「先到先得」的 `decide` 让去重整条失效（预览说入库 7 份、正确是 4 份）→ 去重一律用 `mark`。
2. **口径顺序必须是「版本 → 去重」**：先按文号去重会把同文号的上会稿与定稿件判成互为副本，`kb.version=all`（全抽）于是形同虚设。
3. **`latest_only` 的分组键不能含版本状态**：含了就等于每组各留一份，这个口径等于没实现。
4. **`mtimeMs` 不能用 `0` 当"没取到"的哨兵**：预览与真跑的取舍会不一致（预览说留 `0.` 定稿、执行却写入修改时间更新的副本）。
5. **FTS5 的中文查询不能整串当短语**：`"隐 患 整 改"` 在 unicode61 下匹配不到（单词、两字词正常），要拆成逐字 `AND` 组合。

**没做的部分（如实记）**：① 界面改动只过了 `typecheck:web` + `vite build`，**没有在浏览器里点过**（本会话改前端的老规矩，见第五节）；② 抽取还没在**真实 `3.制度` 目录**上跑过（铁律：要用户明确同意，且第一次只读操作也要先说一声）；③ 扫描件 OCR 那条路只在"没启用 OCR 时应记为 fail"这一侧验证过，真装了语言包**跑通 OCR 入库**没测。

## 三·补四：B3-10 文书↔制度双链（**已落地**，2026-10-02）

**落地物**：迁移 `021_doc_kb_link.sql`（`doc_kb_link` + `kb_change_impact`）；`domain/kb-links.ts`（约 700 行：写链/正查/反查/变更影响/待复核聚合）；`api/routes-kb.ts` 末尾追加 **8 个接口 + 1 个 preSerialization 钩子**（保存成功那一刻写链，与 B3-9 的例外回填同一个钩子位）；`pages/Workbench.tsx` 文件列表新增「制度依据」列 + 依据弹窗（看原文 / 看"被 N 份文书引用" / 人工加 / 取消）。

**关键口径（都写进了代码注释，此处是结论）**：
1. **写链时机**：只有 `/api/generate/save` 成功那一刻写自动链（预览不写）。引用解析**一行都没重写** —— 直接用 B3-9 preHandler 算好的 `ResolvedCitation[]`（`__wbCompliance`）；只有校验引擎抛异常时才退回 `kb-cite.ts` 的 `collectCitationTexts/parseCitations/resolveCitation` 重算。**核不到条款的引用不建链**（只计入 `unresolved` 返回给界面），防"乱连"。
2. **人工链接**：`link_kind='manual'` + `created_by` 留痕；按**条号**比对做幂等（按路径整串比会在制度改过正文后插出第二条"同一条"）。取消是**软删**（`deleted_at/deleted_by/delete_reason` 三列留痕，行不删）。`x-workbench-actor` 头只能放 ASCII（浏览器 fetch 对非 ASCII 头直接抛错），所以留痕支持请求体里的 `actor`。
3. **变更影响**：判据是「制度文件 sha256 + 该条款归一化正文 sha256」的哈希比对（`clause_sha256` 在建链时存下），三态 = `changed / unchanged / clause_removed`；**不做 docx 逐字 diff**，但每条受影响记录都附**该条款现在的正文**，改了什么由人自己看。读点**现算**（几毫秒），`kb_change_impact` 只写历史留痕、**不当缓存读** —— 缓存不失效就会变成"缓存说没变、实际变了"。
4. **软删除读口径**：**读时过滤已删对象，链接行一律保留**。反查（制度→文书）过滤掉回收站里的文书（`inTrash` 如实回报）；正查（文书→制度）过滤掉已不在库里的制度（计入 `stale`），**文书自己在回收站时正查仍可用**（回收站页面要看得出它当初依据了什么）；制度移除后按 `kb_rel_path` 重新入库能**自动认回**（`recovered:true`）。
5. **踩到一个坑（已修）**：`clause_path` 在"一条一行"的制度里会把整句正文吃进去，按路径整段子串匹配时**正文一改就匹配不上**，影响面会误报成"这一条没了"（实测把"每月两次"改成"每月四次"判成 `clause_removed`）→ 改为**先按条号定位**，没有条号才退回路径/名称匹配。

**实测**：隔离实例（临时库 + 临时目录 + 随机端口 + `.tmp` 自造假制度目录与假模板）**76/76 断言全绿**：正查/反查互相核得上、人工加删与留痕、重复保存/重复 resync 不产生重复链接行、无引用文书与悬空条号都不建链、改制度后 impact 判 `changed` 并给出当前正文、文书进回收站/制度被移除的读口径、制度重新入库后自动认回、迁移在**真库副本**上只应用 019/020b/021（除 `compliance_rule` 种子 17 行外逐表行数不变、`quick_check=ok`、外键 0 问题、重复跑为空）。`typecheck` 0 错误、`check-runtime-load` exit 0、`test:unit` 67、`test:regression` 33、`npx vite build` exit 0。

**没做的部分（如实记）**：① 界面只过了 `typecheck:web` + `vite build`，**没有在浏览器里点过**（本会话改前端的老规矩）；② **知识库页没有"被 N 份文书引用"徽标** —— `pages/Knowledge.tsx` 不在本轮文件范围内，这个数字改在文书侧的「制度依据」弹窗里显示（接口 `/api/kb/documents/:id/usages` 已就绪，Knowledge.tsx 接一行即可）；③ 「跳到知识库」只跳转到知识库页、**不能定位到具体条款**（Knowledge.tsx 不读路由参数），条款原文与引用数都在弹窗里直接显示；④ `suggested` 链（出文书时检索命中的"待确认"建议）未实现；⑤ 同一份文书的历史版本（B1-4 的 `version_group`）在反查里各算一份，**未按版本组去重**；⑥ 行政（文书驱动）模式的 `PeriodPanel` 里没有这一列（本轮只加在项目式的「文件」页签）。

## 三·补：B1-4 文书版本管理的两处**有意偏离**（实现为准，已核实）

1. **`POST /api/generate/save` 的接口缺省仍是"新建"**，只有显式传 `saveMode:'update'` 才把旧版归档。
   理由：改缺省会让 `test:e2e` 两条既有断言（"重名不覆盖"的契约）必挂；且"更新"会**移动磁盘上用户已有的生成文件**，属破坏性动作，不该在调用方没要求时发生。文档要的"默认"落在**弹窗默认项**（生成弹窗默认选中「更新这一版」）。
2. **版本链的组键是四元组**（`工作台 + 模板 + 清单项 + position_code`），文档原写三元组。
   理由：同一模板在两个阶段各出一份，用户眼里是两份文书；按"宁可多一条链也不错串"收紧键。同一四元组下允许多条链（选「新建」），此时"更新这一版"跟**最新**那条链。

另：`docs/12-备份与还原.md` 已补（179 行）；顺带修好"**界面备份设置读不回来**"（`Settings.tsx` 写 `backup.*`、`loadBackupConfig` 只读裸键 → 关不掉自动备份；改为读侧两种键都认，并在 `config.ts` 登记 `backup.*` 且值留 `null`，避免种值压住 `workbench.config.json`）与"**只在启动时 auto 为真才建定时器**"（导致重新打开也不生效）。这是"界面声称能设、后端不生效"的第 4 例。
