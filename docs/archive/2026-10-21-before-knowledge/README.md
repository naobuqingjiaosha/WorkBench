## 快速开始

以下用于首次安装或已获准启动的本机环境。现有日常服务维持暂缓发布决定；不要为试用新代码自行重启日常实例。启动会执行迁移与初始化，隔离试用须使用独立数据与运行目录。

```powershell
npm start
```

默认本机入口：[工作台](http://127.0.0.1:8787/)。此地址不表示本次已检查服务可用。

第一次使用请按顺序做三件事（详见 `docs/02-快速上手.md`）：

1. 「系统配置 → 模型服务商」填 API Key 并测试连接
2. 在「知识库」中的模板入口上传用`{变量名}`改造过的Word/Excel模板
3. 「我的工作台」新建工作台，流程和清单自动生成

### 使用 LM Studio 本地模型

1. 在 LM Studio 的 Developer 页面启动本地服务，并加载需要使用的模型。
2. 工作台「系统配置 → 本地模型 · LM Studio」填写服务地址，默认 `http://127.0.0.1:1234/v1`。仅启用了身份验证时填写 API Token。
3. 点击「检测连接 / 获取模型」，选择或填写模型标识，点击「保存并启用本地模型」。文书写作、信息抽取、复杂推理和 AI 助手会一起切换。

图像模型需支持图片输入，向量模型需支持 Embeddings，AI 助手需支持工具调用。图像或向量模型留空时停用对应模型用途，避免继续使用云端配置；本地服务失败不会自动回退到云端。

接口：`POST /api/ai/local/models` 检测连接并获取模型；`PUT /api/ai/local` 保存并切换配置。请求体支持 `baseUrl`、可选 `apiKey`；保存还需 `model`，可另传 `visionModel`、`embeddingModel`。修改接口沿用本机会话鉴权，需请求头 `x-workbench-token`（从 `/api/session` 获取）。本地接入地址限定为本机回环地址。

协议依据：[LM Studio 兼容接口](https://lmstudio.ai/docs/developer/openai-compat)。已有云端配置不会在打开页面时被自动改写，只有主动保存本地配置后才切换。

## 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | Node.js ≥ 24 | 后端使用原生TypeScript类型剥离，前端需Vite构建 |
| 数据库 | **内置 `node:sqlite` + FTS5** | 零原生编译、零安装风险；单文件数据库；中文用"逐字空格化 + 短语匹配"做全文检索 |
| 后端 | Fastify | 一个进程同时提供 API、静态文件和 Web 界面 |
| 前端 | React 19 + Vite | 构建产物由后端直接托管，单一端口 |
| 文档处理 | PizZip（docx XML 级替换）+ ExcelJS | 只替换文本节点，排版/公式/样式 尽量保留（变量之外的样式保持，长文本需检查分页） |
| PDF文字提取 | pdfjs-dist | 文字PDF本地提取；扫描PDF仍待转图片与OCR接入 |
| 扫描件识别 | tesseract.js（纯 WASM） | 不需要安装 Tesseract 程序；语言包本地缓存，离线可用 |
| 向量检索 | SQLite BLOB 存 Float32 + 内存余弦相似度 | 万级片段以内不需要向量数据库，零额外依赖 |
| 模型接入 | OpenAI 兼容协议（手写 fetch） | 一套代码适配 DeepSeek / 通义 / 智谱 / Kimi / Ollama / 各种中转站 |

暂存前端构建可执行`npm --workspace @workbench/web run build -- --outDir D:/project/工作台/.tmp/web-stage-review`，目标须为新的独立绝对目录。当前没有`npm run build:staged`脚本；暂存构建不会切换日常服务。测试统一通过现有隔离启动器执行，不直接运行测试文件。

`npm run reset`会清空业务数据，仅在明确授权并核实目标后使用，不作为自检。`db:init`、`samples`及启动命令也会写入所配置的数据目录。

## 环境注意事项（Windows + 受限沙箱）

在受限环境下开发时踩到的坑，记录备查：

- 若受限沙箱中的默认npm缓存不可写，可显式指定项目内缓存；历史环境曾使用`npm install --cache <项目内路径> --ignore-scripts`，是否跳过安装脚本须按实际依赖判断。
- `npm run build` 需要允许 esbuild 启动子进程，受限沙箱下会报 `spawn EPERM`
- 后端不需要任何构建步骤，Node 原生剥离类型；`tsx` 在受限环境下不可用（依赖 esbuild 服务进程）
