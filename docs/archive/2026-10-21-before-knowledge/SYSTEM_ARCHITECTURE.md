- `business-evidence.ts`负责收集与来源新鲜度；`evidence-task.ts`在原快照上建立任务视图，筛选业务事实、冲突与正文缺口，不改写原始证据或统计口径。
- `evidence-writing.ts`调用writing用途生成结构化自然段，每段保留字段、事实/分析/建议类型、事实ID和原文锚点。程序核对字段、数字、日期、状态、缺失范围及争议支持；统计使用程序指标占位符。

## 月度检查办理简化（第四轮）

- `inspection_record` 按期次保存项目、日期、监督事项、内容、结果、整改情况及修订号。生成接口校验工作、期次、记录和修订归属，防止窗口打开后记录变化仍保存旧内容。
- `artifact.inspection_id/inspection_revision` 关联检查成果；检查及修订分别使用现有版本链，修改记录后旧成果仍保留，但不计入当前记录定稿。回退保留期次和检查归属。
- `period_material.requirement_kind` 区分生成件、外部证明、参考资料及实际报送。迁移仅分类已知内置名称；自定义要求默认保留外部证明规则。
- `periodReadiness` 是界面、待办与完成接口共用的业务校验：检查记录、适用模板实际定稿文件、外部证明实际文件和人工核对、明确报送日期及成果快照。旧步骤不再构成期次完成条件，后台记录继续保留。
- 工作详情不请求操作日志；按记录生成与成果刷新共用现有生成、预览、文件及版本能力。附件按需上传核对，参考资料默认折叠；不新增工作流引擎。

## 运行结构

```text
浏览器（React 19 / TypeScript / Vite，hash 路由）
    ↓ HTTP API + 本机会话请求保护
Fastify 单进程（API、静态文件、SPA 回退）
    ├─ domain：工作台、期次、生成、工时、版本、记忆、工作流
    ├─ core：模板、文件、路径、OCR、检索、备份、健康状态
    ├─ ai：模型档案、统一网关、本地模型、外发确认
    ├─ node:sqlite：业务元数据、FTS 索引、日志、迁移
    └─ 磁盘文件：模板、资料、影像、生成件、备份
```

运行时要求 Node.js ≥24。根目录 npm workspaces 管理 `packages/server` 和 `packages/web`。标准启动器直接运行 TypeScript 后端；前端生产构建由后端托管，默认地址 `http://127.0.0.1:8787`。

## 关键处理链路

1. **文书**：选择工作及阶段/期次 → 模板与档案/材料/记忆准备 → 按本次请求决定是否检索制度 → AI 或字段填充 → Office 渲染 → 预览 → 实际文件及缺项校验 → 草稿/定稿、版本记录、归档与索引。
2. **制度**：保留来源文件 → 文本抽取和条款切块 → SQLite 本地关键词/全文检索 → 引用来源；默认制度检索不请求向量模型。不要将旧向量能力视为当前默认路径。
3. **周期**：规则同步创建独立期次及快照 → 提供/核对材料 → 生成文书 → 核对缺项和定稿 → 确认期次完成。
4. **工时**：导入同月 XLSX → 核对姓名、项目和考勤 → 研发优先计算 → 校验异常 → 导出副本及校验记录 → 用户核对和定稿。
5. **外部模型**：网关准备目标、用途和请求摘要 → 单次确认 → 发起请求并记录；拒绝、过期或摘要不一致不能发送。本地回环模型有独立配置约束。

## 架构约束与维护决策

- 普通文件可直接读取；SQLite 负责业务关系和索引，备份策略要同时考虑数据库及文件。
- DOCX 使用 PizZip/XML 处理变量、循环及图片，XLSX 使用 ExcelJS；保持既有格式但长文本、分页和打印仍须 Office 验收。
- OCR 使用 tesseract.js/WASM 和本地语言缓存；扫描 PDF 转图片仍是缺口。
- 本机会话写请求使用 `x-workbench-token` 等保护，具体逻辑见 `core/request-guard.ts`。
- 阶段/期次快照及实例目录隔离配置变化；模板历史从本轮之后的受控修改开始保留，不能恢复此前已经丢失且未备份的旧版本。
- LM Studio 地址限制本机回环；未配置视觉/向量模型则停用对应用途；失败不自动改用云模型。
- 不引入复杂分布式部署或新的向量数据库，除非用户明确变更范围。
