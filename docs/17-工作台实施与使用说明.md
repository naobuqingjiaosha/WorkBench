# 工作台新增流程使用说明

本次在原有 React / Fastify / SQLite / ExcelJS 项目上增量实现，没有新增框架或运行依赖。数据在本机保存，演示和测试使用独立数据库。

## 启动与匿名试用

在项目根目录运行：

```powershell
npm run typecheck
npm run build
npm run demo:workflow
```

演示页面为 `http://127.0.0.1:18878`，包含匿名安全月报、清廉季报、项目清单、四种月份长度的工时样例。每次演示新建 `.tmp/workflow-*`，不接触业务数据库，外部模型请求在测试模式中被阻断。按 Ctrl+C 结束。

只生成样例：`npm run demo:workflow -- --generate-only`。生成目录含工时 XLSX、数据库备份和 `验证记录.json`。

实际使用运行 `npm start`，默认打开 `http://127.0.0.1:8787`。首次升级前在原系统“系统配置 → 备份与恢复”做一次数据库备份，同时备份用户文件目录。本次迁移 023—025 为新增表和字段；旧文件不会被自动编入新期次。

修复后的人员别名、阶段要求快照及记忆事实确认操作见 [20-审查问题修复与回归验证](20-审查问题修复与回归验证.md)。

## 模板填充与制度参考

制度参考默认关闭。普通生成只使用模板、本期材料和已确认事实，不检索制度，不注入制度检索正文；打开生成窗口、预览和保存不自动调用制度设置、条款或校验接口。

制度入库只抽取原文、按条款切块并建立本地关键词索引，不向量化。检索可使用制度名称、文号和正文关键词，不依赖 Embedding 模型；原有向量不参与检索。检索提问中的“问它”只允许本地写作模型接收原文，未配置本地模型时仍可直接检索并查看原文。

只有当前聊天消息或本次生成要求明确写出“帮我参考制度”时，才对这一次启用制度检索。否定、转述或引用这句话不会启用。生成结束或失败后恢复关闭；旧聊天、模板设置及旧勾选参数都不能延续开启状态。

临时启用时仍展示检索到的制度名称、文号、条款位置和原文。制度要求不能替代本次工作事实，检索命中也不代表内容已经合规。新文书不会继承模板的旧必查设置；已保存文书的历史要求快照保持原有约束。

首次使用此功能，正常启动时会应用新增表迁移 **026**。本轮只在隔离样例库验证，没有升级真实业务库。升级前保留数据库及文件目录备份。

## 周期报送操作

1. 创建行政管理工作，绑定实际模板；在工作详情“周期报送 · 独立期次”设置频率、首个报告期、截止月份偏移、日号及必备材料。
2. 截止月份从报告期的**首月**计算。例如 2026-Q3 首月为 7 月，偏移 3、日号 10 表示 10 月 10 日；月报偏移 1 表示次月。日号 31 在短月份取月末。
3. 页面补齐首期到当前日期的期次，重复操作不会重复建期。规则变化只影响后来创建的期次。旧期的截止日期可单独改。
4. 选中报告期，直接上传材料，或关联本工作已有文件。上传只标记“已提供、待核对”；核对后确认符合要求。不适用必须填写原因。
5. 填写本期事实、保存内容、生成对应模板。自动年月字段采用报告期，实际写作日期仍为当天。本期生成只使用明确关联的本期资料和适用记忆，不自动继承上期数字。
6. 下载查看、修改字段、生成草稿或定稿。版本链按报告期隔离，历史无期次版本不自动归入本期。
7. 确认已经上报后完成本期。必备材料未核对、文件丢失或尚缺定稿时阻止完成。补办旧期不改变新期。
8. 模板文件或变量说明发生变化时，先查看并确认本期模板差异。已有定稿保留；若需更改已完成期次，先重新打开。

匿名排期参考见 `examples/周期规则样例.json`。实际材料要求和截止日期应按通知填写。

## 部门工时

1. 左侧进入“部门工时”，设置目标年月，分别导入部门模板、研发明细、考勤 XLSX。保存的是副本；不覆盖上传源文件。
2. 根据输入预览设置工作表、起始行和列号。研发支持纵向人日表或横向日期表；考勤使用逐人逐日表。公式必须已有 Excel 计算结果。
3. 部门模板工作表名称为“工时明细表（填写）”，C 列人员、E 列正式项目、I 列起完整日期，行末为本行 `SUM` 月合计。模板天数须与目标月份匹配。
4. 输入本月正式成立项目和“人员=项目”默认归属，确认研发记录完整。人员和项目采用精确名称；简称、别名需要在本地输入副本中核对统一。
5. 逐日考勤必须明确提供，休息日也要填写；不按星期推断调休或节假日。不计项目工时的活动包括请假、调休、考试、承揽业务、技术交流、洽谈项目。
6. 研发优先扣除，部门工时不超过 `8－当日研发工时`。研发超过 8、重复考勤、未知活动、未明确项目、缺少考勤等均列为异常并阻止定稿。
7. 半天或混合活动点击“人工确认”，填写部门小时数、正式项目和依据，然后重新计算。输入或调整变化后旧结果仍保留，必须重新计算才能定稿新结果。
8. 下载工时表。输出保留模板样式、合并单元格及说明工作表，加入逐人逐日计算依据、规则版本和异常校验页；异常版明确标记草稿。
9. 在 Excel/WPS 实际核对后勾选确认、定稿。历史运行输入、映射、源文件摘要、计算结果与规则版本保留。

当前模板缺少人员项目行时，不会自动插行破坏原有结构：请在模板副本中新增行和本行月合计公式后重新导入。PDF 考勤需要先在本地整理为经过人工核对的 XLSX。

## 项目材料核对

原流程阶段和清单继续使用。详情中“项目材料核对”逐项关联文件并确认符合要求；不适用必须有原因。上传数量达标不等于内容符合要求。阶段完成和整个工作完成均检查必备材料核对状态及实际文件；阶段绑定的必备生成文书需要实际定稿文件。

匿名项目只演示阶段和清单，不代表公司合规制度。须录入真实项目阶段、交付要求、验收清单后验收。

## 外部 AI 发送确认

外部模型对话、写作、图片识别、工具结果继续发送和资料向量化均经过网关确认。确认窗口显示目标地址、模型及实际请求内容；只批准这一份确定内容，拒绝或超时不发送。请求内容变化、重试和后续模型调用需要新的确认。进程重启不恢复未完成外发。

API Key 不显示在预览内。确认处理后清空待发内容，历史仅保留调用摘要和状态。回环地址的本地模型不弹外发确认；地址不能通过 HTTP 重定向转向外部。远程服务不可达时发送可能失败，不能将失败状态理解为模型已完成工作。

## 待办、记忆、知识库与备份

- 首页“近期办理”支持标题、截止日和备注快速登记待办；周期提醒可直接进入对应期次。
- AI 助手的记忆面板可更正内容、来源、工作/期次范围、生效与失效日期，或停用。只使用已确认、未过期、适用于当前工作的记忆；本期事实优先，冲突仍需人工复核。
- 继续使用原知识库有效版本、检索与引用能力；上传制度时维护来源和版本，废止内容不要作为当前依据。
- 系统配置提供数据库备份、校验、恢复。数据库备份**不包含**用户文件或工时输入副本，完整迁移必须同时备份实际文件目录（含 `_工时处理`）。恢复旧数据库后比备份更新的记录不会存在，但文件不会自动删除。
