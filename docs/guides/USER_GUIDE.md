# 使用说明

文档ID：GUIDE-USER。版本：1.1。更新：2026-11-06。适用：当前日常月度工时、年度台账及检查草稿版本；具体运行状态见[开发进度](../../DEVELOPMENT_PROGRESS.md)。

## 1. 进入与理解页面

使用根目录“启动工作台.cmd”或已启动的[本机工作台](http://127.0.0.1:8787)。已有页面能打开时不必重复启动。遇到端口或启动错误按[运维手册](OPERATIONS.md)排查。

首页看当前事项；“我的工作台”进入具体工作；“流程规范”维护类型和适用规则；“模板库”维护可重复使用的Word/Excel；助手用于问答和起草。工作记录属于未发布候选，当前日常版不能按候选截图寻找该入口。

## 2. 新建工作

选择行政管理或项目工作。项目再选择信息化/工程目录和具体类型；目录只是分类，实际流程由具体类型决定。填写已知的名称、背景等信息，按需要选择适用模板。流程配置候选只提供已发布且未停用类型，新工作采用选择时的发布配置；如提示版本变化，点击“刷新可用配置”，核对所选类型后重试，基础输入保留。一份模板都不选表示当前工作暂不使用模板，不自动采用整个模板池。

工作、月份/季度/年度、项目阶段是不同范围。进入材料前先确认当前是哪项工作、哪一期或哪个阶段，避免把历史资料当成本期。

### 2.1 维护流程配置（源码候选，未发布为日常版）

1. 打开“流程规范”，选择类型或点击“新增 / 复制类型”。空白或复制均先建草稿；复制只取已发布规则与模板引用，不复制业务资料。
2. 编辑类型说明、导航分类、阶段顺序/要求、影像、模板和周期规则。材料明确选择外部材料、参考资料或生成成果；旧规则兼容项在复制或改名后应明确用途。已有工作使用的类型不能直接更改领域、业务分类、办理方式或执行器。专用月检能力不会因复制或改名获得。
3. “保存草稿”只保存编辑；不完整内容可以保存，结构错误或发布前缺项会提示。离开时可继续、放弃未保存输入或保存并离开。另一个窗口已改时，保留本页内容，先“核对最新状态”，比较后采用最新内容或明确保留本页整份配置、以最新修订为基线重新保存。
4. 保存后“检查差异并发布”，检查实际变更、填写变更说明，再“确认发布配置”。这是本地规则版本发布，不是软件部署。期间等待完成，失败保留草稿；网络结果未知先核对最新状态。历史版本保留，放弃已保存草稿须明确确认。
5. “停用新建”只从新建选项中移除类型，旧工作仍可查询/办理且周期继续；“恢复新建”恢复现有发布版，不自动发布未完成草稿。工作列表仍保留停用类型分类。

发布新规则默认只影响以后创建的工作。在已有工作详情的“流程配置更新”点击“预览配置差异”，查看可应用项和禁止原因，再勾选指定范围及确认框，点击“确认应用所选范围”。新增阶段仍待开始；显示名称、说明、顺序及文书要求仅在未使用的安全阶段可改，目录不搬移。既有材料/影像要求、已完成或有业务引用的阶段不可覆盖，不能以配置更新改历史定稿。周期工作须填写明确未来生效期并重新预览；频率不变且晚于今天、已有期次和已排定规则。应用不生成期次、不改旧期次，后续正常生成才采用对应规则。已排定规则不原位撤销/修改，可安排更晚的不同规则；旧高级排期保存会明确拒绝覆盖。页面记录实际部分范围，不代表整项工作全部升级。失败保留选择，可重试；冲突须重新预览并再次确认。慢请求期间等待完成，取消未保存选择须明确放弃。旧实例来源不明确时保持原兼容逻辑。模板内容或变量配置变化会与已保存指纹冲突。对有明确发布来源的工作/阶段，“预览阶段模板要求变更”与“流程配置更新”执行同一保护；漂移、归档或缺失会禁用应用，预览后才发生变化也会拒绝确认，不会把新文件指纹自动当成批准。应核对模板并明确重新发布适用配置，再重新预览；不能靠重试强行覆盖旧引用，历史成果保留。配置不生成检查/工时事实，也不管理实际报送。阶段模板未指定的新实例保持空绑定。

周期配置的多项生成成果可以共用同一模板。生成窗口的“本次对应成果要求”明确选择这份文件对应哪项；只更新所选要求和该项版本链，不自动满足其他项。“逐项成果要求”分别显示必备/选备与有效成果状态，导入或已有文件可在对应行明确关联；同模板或同名不代表已经关联。单项可自动选中；多项未选时不能保存。缺任一必备项仍不可完成，但不阻止其他草稿保存或下载，生成也不自动办结。关联保存进行中请等待，导航或返回会提示留在原页；失败保留选择并显示错误，可点“重试关联”，或“放弃未保存选择”恢复已保存关系。离开确认中的“保存并离开”须保存成功才离开；“不保存离开”只丢弃未保存选择，不删除既有关联。空选项不是清除关联操作。

## 3. 月度检查材料

清廉工程月检优先从期次内“年度台账与月度检查”开始：导入/绑定原年度台账 → 选择项目并查看历史 → 保存本月事项和实际情况 → 标记两条小微权力记录 → 补齐/采用模型建议 → 从同一记录生成工作记录表与监督情况表。允许同项目同月多条；未选项目不自动结束。外部Excel保存后，点击读取修改并同步，冲突时选择保留内容。完整步骤见[月度工作指南](MONTHLY_DEVELOPMENT.md)。

以下共享草稿入口继续保留，用于原有材料准备场景：

1. 进入月检工作，选择本月，点击“新建检查记录”。也可在助手选中月检工作后说“帮我准备本月检查材料”。
2. 系统先参考同工作历史，标明来源。没有历史时可先填写项目背景，不必补造检查日期或结果。
3. 模型可用且资料使用范围允许时给出文字建议；用户可以直接编辑，也可在共享草稿卡片选择修改范围并提出要求。
4. 未开展或缺少事实时保存草稿、下载待确认文件；不得把建议当已开展的检查。
5. 实际情况明确后，集中核对并“采用并生成文件”。项目、日期、主题、内容、结果齐全才会形成实际检查记录；特定模板所需检查人等仍需补齐。
6. 选择适用的单次模板生成，逐份查看结果。月度/年度汇总从对应汇总入口生成，不能拿汇总模板当单次模板。
7. 下载后检查内容和版式。Word页面摘要不等于完整分页预览，Excel页面预览不等于桌面打印和公式重算。

可以直接取得草稿文件，不需要登记报送日期、上传回执或先点击本期完成。工作台不管理是否实际报送。

## 4. 修改、旧文件与恢复

- 草稿修改后保存；其他入口已更新同一草稿时，系统可能提示冲突。保留自己的输入，核对最新内容后再保存，不能反复强行覆盖。
- AI建议与原文可对照，仅采用需要的修改。请求失败时原稿保留，可人工继续。
- 历史来源被更正或删除时，先切换来源或解除引用，不继续把旧引用当有效依据。
- 内容或模板变化后旧文件仍保留，可能显示待更新；再次生成取得新版本。不能只看旧文件名判断当前内容正确。
- “生成成功”“定稿”“检查已开展”“业务结束”含义不同。可自愿保留核对后的定稿，草稿下载不依赖它。

筛选只影响列表，新记录须在上方补充信息中明确选择关联；不自动继承当前筛选。记录与项目名相似也不会自动合并。查看关联不改变期次、阶段、清单或完成状态；列表条数不是完成事项数。详情显示存储进度。外部移走、恢复或替换资料后，点击详情上方“重新核对材料与进度”：它会按当前磁盘文件更新影像数量、清单状态及完成时间、工作进度，不改变阶段/期次办理状态或历史定稿；普通刷新页面只读取已有值。核对中等待完成，失败可直接重试，未保存表单输入保留且不参与核对。系统内上传、删除、恢复及定稿标记变更会同步关联工作，无需改无关字段或重启纠正计数。恢复或定稿/取消定稿若收到同步失败响应，其主动作和派生数据会一起回滚；排除故障后重试原操作。恢复成功后再次恢复仍提示“不在回收站”，定稿同值重复则提示无需修改；这与首次失败后的重试不同。网络中断而未收到明确响应时，先查看当前状态，不据超时猜测成功或失败。

## 5. 项目、季度材料与工时

| 场景 | 使用要点 |
|---|---|
| 在办项目 | 按实际类型阶段处理，区分参考资料、生成件和真实合同/签章/验收证明 |
| 历史项目 | 补录已有事实和资料，不重走历史；未知结束日期不编造 |
| 季度材料 | 明确选择来源工作和期次；检查跨期、缺资料与计划/实际差异，再编辑正文 |
| 部门工时 | 从所属月度期次进入，选择月份，使用页面顶部研发/考勤/模板入口；确认名单、应计日期和扣薪例外，生成后手动或经模型建议修改，再核对导出。完整步骤见[月度工作指南](MONTHLY_DEVELOPMENT.md) |
| 制度参考 | 默认关闭；需要时明确提出本次参考制度，并人工判断适用范围 |
| 工作记录候选 | 源码已支持原话录入、查询、更正和撤回，但当前日常包未包含，不属于当前操作承诺 |

整数小时是用户已确认规则，本次按要求暂不改算法和旧9月文件；当前自动分配仍可能产生小数。发布完成不等于此项已实现。

## 6. 模板和资料

模板是空白结构及填写规则，不是已经发生的事实。目录筛选用于寻找模板，同一模板可适用于多个流程。不要仅凭模板名称改变工作类型。

制作细节见[模板制作指南](../03-模板制作指南.md)，以当前模板引擎和实际产物检查补充旧指南。Word变量使用单一格式运行中的 `{变量名}`；Excel循环/集合行须在数据区末尾且不合并、不含公式，不在后面放页脚。

上传后检查变量、示例生成和实际版式；不能只做文件盘点就宣称模板可用。外部真实原件保留，参考目录只读。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 模型未配置或请求失败 | 保存草稿并人工编辑，确认设置和资料使用范围，不自行复制凭证或改用外部服务 |
| 生成后仍有“待确认” | 看模板列出的缺项；不是每份模板都只需要核心五项事实 |
| 旧文件显示待更新 | 核对来源/模板/记录变化，再生成新版本；旧稿可保留参考 |
| 日期或结果不知道 | 保持未知并下载待确认稿，不填“无问题”凑齐 |
| 进入不了或界面版本不符 | 按运维手册核对服务、发布指针和前端，不直接启动开发源码替代 |
| 删除出现错误 | 保留提示与对象范围，停止重复永久删除，按GOV-01隔离排查；不要手工清理数据库 |

## 8. 提交有效反馈

记录要完成的业务、工作/期次范围（必要时匿名）、操作步骤、期望与实际、错误提示、时间、是否保留输入及文件。提供资料时按需脱敏；不要包含模型密钥。当前待验收项见[质量计划](../management/QUALITY_AND_ACCEPTANCE.md)。
