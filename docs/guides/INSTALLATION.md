# 安装与启动指南

文档ID：GUIDE-INSTALLATION。版本：1.8。更新：2026-11-12。性质：当前源码的安装、更新与已有环境接续。

## 首次使用

安装 Node.js 24 和配套 npm 11（其他 npm 主版本尚未适配，会明确停止准备），取得完整仓库后，双击根目录的 `启动工作台.cmd`。不需要先手工运行 npm ci 或 npm run build；启动器会在本机私有缓存准备依赖、构建界面，然后打开浏览器。需要足够磁盘空间；没有可核对的已安装依赖且缓存不完整时才需要访问 npm 依赖源。默认地址为 http://127.0.0.1:8787，以启动窗口显示为准。

新安装的配置和数据默认位于 `%LOCALAPPDATA%\WorkBench\daily`，不会随 Git 传递。已有安装继续使用原配置、数据库、模板和业务文件路径，不自动搬迁。需要自定义时使用绝对路径的 WORKBENCH_HOME；样例 workbench.config.example.json 只说明格式，不要覆盖已有配置。相对路径规则见[资料边界](DATA_BOUNDARIES.md)。模型、OCR 和 Office 仍按实际功能另行配置。

## 唯一日常入口

双击 `启动工作台.cmd` 后，浏览器打开，启动窗口保留。停止时先保存网页中的输入，再回到启动窗口输入 **S** 并按回车。若直接关闭窗口，服务继续在后台运行，再次双击即可重新打开控制窗口。

`npm start` 是同一启动链的终端方式，`start:auto` 为兼容别名，端口冲突不另开实例。候选预览双击脚本和 `preview:candidate` 已移除，既有 candidate 数据不删除、不迁移。`--last-good` 与 `--release` 仅供明确故障恢复，不是日常多版本选择器。

## 拉取后双击使用最新代码

在原仓库目录执行：

```powershell
git status --short
git pull --ff-only origin main
```

有本地修改、分支分歧或 pull 冲突时保留现场，先解决差异，不使用 reset 覆盖自己的文件。拉取成功后，双击同一目录的 `启动工作台.cmd` 即可。也可在终端执行 `npm start`；后者前台运行，Ctrl+C 停止。

默认入口按当前磁盘源码构建，包含已保存的本地源码修改；它不自动拉取 Git，也不承诺绕过冲突取得远端最新。工作台已运行且源码未变时，再次双击会核对版本和数据位置，直接打开页面，跳过依赖检查、测试编译和数据库迁移查询；源码变化时先准备新的配套界面与依赖，成功后提示先保存所有浏览器输入，再输入 Y 确认重启。更新后刷新原页面。优先核对并复制上次可用副本或本仓库已安装的依赖；检查安装记录、版本、依赖图及关键运行入口，不直接把node_modules存在当作完整。无法复用时先用原npm缓存离线安装，缺项才联网；锁变化后按当前锁重新核对或安装，不静默启动旧源码。

旧版后台进程没有安全停止接口时，第一次接续会明确停止更新。保存输入并关闭旧服务；找不到旧服务启动窗口时，可重启电脑，再双击仓库入口。无需盘点或删除多个历史版本。新入口的后续更新会核验实例身份并等待请求、数据库锁和已开始的后台任务结束，不强杀进程，也不自动换端口启动另一份工作台。

**已有数据库需要新增迁移时会列出迁移并要求确认。** 确认后先保留升级前数据库备份，并在副本演练；新迁移作为一批事务执行。失败保留日志及备份，不自动覆盖业务数据或倒回旧库。没有迁移记录的非空库、当前代码不认识的较新迁移均拒绝猜测启动。空白新安装正常初始化；备份不包含外部原件或全部业务文件。

npm缓存沿用在原仓库解析的配置（本项目默认.npm-cache，也支持用户配置及环境变量）；相对缓存路径不会因临时构建目录而变成另一个空缓存。npm子进程从原仓库读取项目及用户配置，保留环境覆盖和相对cafile等路径语义；不复制.npmrc到准备或完成副本，异常中断也不产生这份凭据副本。原依赖、缓存和配置不被删除；没有可核对的安装记录或缺少所需包时，离线启动可能仍需补全缓存或联网安装。

## 失败与恢复

- 安装或构建失败：原服务继续运行，原数据库和成功版本记录不变。检查启动窗口中的错误（网络、磁盘空间或源码问题），修复后重新双击。
- 已建缓存损坏：同样在停旧服务前检查安装记录、依赖图、模块入口及esbuild；失败显示具体副本目录，不先停止活动服务。先核对npm 11及错误原因；确需重建该副本时，保存输入并停止使用它的服务，将提示的单个缓存目录移到source-builds之外保留，再双击重建。不要删除数据、备份或source-current记录，不移动仍在运行的副本。
- 准备成功后停止/备份/迁移/新服务失败：窗口说明阶段与日志位置，不自动反复重试或启动旧程序。先核对是否仍有实例运行，以及数据库是否已升级；不要删除锁或直接覆盖数据库。
- 明确使用本目录上次成功的源码副本：`node scripts/start.mjs --last-good --background --start-only --open`。仍须通过源码/界面及依赖可用性、环境身份和迁移兼容检查；不存在已验证副本就拒绝。数据库已升级到该副本不认识的版本时不能回退程序。
- 历史发布包仅保留显式恢复入口：`node scripts/start.mjs --release --background --start-only --open`。须先停止当前服务，核对原发布包、前端及数据库兼容；此入口拒绝执行缺失迁移或降级。旧 current-release.json 不再控制默认双击，不必删除或手改它。

缓存位于仓库 `.local/source-builds`，每份含配套源码、依赖、界面及 SOURCE_BUILD.json；成功记录为当前运行根的 source-current.json。只运行一个工作台，但保留可核验缓存与备份供恢复，不自动清理用户历史。缓存、私人配置、业务数据、私有测试和运行日志留在本机。共享合成回归随源码提供。详细排障见[运维手册](OPERATIONS.md)。

## 内部开发与测试

`dev:monthly`、`dev`、`server` 仅用于开发验证，沿用独立 development 数据根和18889，不作为用户日常入口。隔离测试保留，详见[开发指南](DEVELOPMENT.md)。不要删除旧预览目录中的资料来收敛入口。

当前构建为锁定的esbuild启用标准输入输出传输适配，避免大文件转译的临时输入删除通道；启动准备仍执行超过1 MiB的真实转译。依赖适配不匹配会明确停止，不能跳过检查。安装失败只有明确的ENOTCACHED会尝试获取缺项一次；Access denied/EPERM/EACCES、空间及未知错误直接停止，保留原始诊断，不反复安装。

出现拒绝访问时保留原文件和日志，核对报错阶段、路径及运行身份。不得以Git hook的“无Git元数据”提示解释构建失败，不自动改ACL、完整性标签、安全软件或提权。云端修复是规避已知传输路径；普通桌面与Low Mandatory Level工具沙箱的临时根和权限不同，不能相互代验，也未据此确定原文件占用或执行完整性根因。

启动是写操作，会按上述规则初始化或升级当前环境，不可作为只读探测。Windows 双击、原生文件锁、真实旧安装和 Office 的实际结果须在目标设备核实；云端 Linux 隔离验证不能代替这些验收。
