# 源码、测试和本机资料的边界

文档ID：GUIDE-DATA-BOUNDARIES。版本：1.3。更新：2026-11-12。适用：运行架构、Git源码交付与默认程序包。

## 1. 哪些内容上传

| 类别 | 位置 | 是否进入Git |
|---|---|---|
| 应用代码 | packages/server/src、packages/web/src及迁移 | 是；含旧版Excel转换运行工具，演示资料生成CLI例外 |
| 依赖及构建规则 | package.json、锁文件、tsconfig、Vite配置 | 是，属于可复现构建所需代码配置 |
| 通用工具 | scripts中明确允许的启动、备份、隔离运行器、打包及检查脚本 | 是 |
| 开发文档 | 根入口、docs/guides、docs/management、指定技术索引 | 是，不能写入真实资料正文或凭证 |
| 配置样例 | workbench.config.example.json | 是，仅通用相对路径和默认值 |
| 本机配置 | workbench.config.json、.env及私有配置 | 否 |
| 共享验证 | packages/server/test/shared/*.ts | 是，只收录经审查的合成用例、生成器、非敏感断言 |
| 私有验证 | 其他本机用例、资料、样本、截图与生成文件 | 否 |
| 真实业务资料 | data、外部绑定目录 | 否 |
| 临时数据与报告 | .tmp、outputs、work、历史扫描/验收报告及ACL产物 | 否 |

`scripts/repository-policy.mjs`定义允许上传的路径，`.gitignore`配合默认排除未知根目录。应用代码、共享文档中的真实内容仍需人工审查，不能把文件后缀当成保密判断。

## 2. 三个独立区域

1. **源码区**：前后端代码、SQL迁移、依赖声明、通用工具和开发文档。新电脑从Git获取这一部分。
2. **测试区**：共享回归从源码构造样例，私有回归与真实资料单独保管。每个共享用例在自己的临时根运行并清理。
3. **本机资料区**：业务文件、数据库、模型设置、凭证、扫描报告和运行快照保留本机。已有路径及运行配置没有因本次Git隔离而迁移。

运行环境由统一路径模块解析；上传策略作为第二道边界。二者都不构成操作系统权限沙箱，用户明确绑定的外部原件仍按应用的只读/可写规则访问。

## 3. 运行架构与首次配置

`packages/server/src/core/runtime-layout.ts`是统一环境入口，只解析路径和私有配置，不打开数据库、不创建目录。启动器、应用配置、备份、文件删除保护、OCR及升级工具使用同一套路径约定。

```text
源码目录                         只含代码、依赖、通用配置样例与文档
独立环境根/workbench.config.json  本机配置
独立环境根/files/                业务文件
独立环境根/runtime/              SQLite、日志、锁、OCR缓存
独立环境根/backups/              备份
私有测试用例和夹具                单独保管；共享用例从源码生成输入
系统临时目录/workbench-isolated-* 测试每次新建，用后清理
```

| 模式 | 入口与默认位置 | 配置来源 |
|---|---|---|
| 日常daily | npm start；Windows的%LOCALAPPDATA%/WorkBench/daily | 当前环境的workbench.config.json |
| 开发development | npm run dev / npm run server；WorkBench/development/源码路径摘要 | 独立开发根的配置，不读取日常配置 |
| 测试test | test-isolated；带归属标记的临时根 | 不读取配置文件，只接受隔离入口提供的完整路径 |

非Windows默认使用XDG_DATA_HOME，未配置时使用用户目录下.local/share。`WORKBENCH_HOME`指定日常独立根，`WORKBENCH_DEV_HOME`指定开发根，均必须为绝对路径。`WORKBENCH_DEV_PORT`同时控制开发后端和代理，默认18889。显式资源变量仍优先于当前环境的配置字段；配置相对路径以环境根解析，不能依赖启动时的当前目录。

新安装不需要根目录真实配置。首次启动生成当前环境的私有配置；如需提前配置，可将通用样例复制到环境根。`WORKBENCH_CONFIG_FILE`只接受已有的绝对文件路径，配置错误或不存在时拒绝回退到其他环境。新布局拒绝把可写数据/配置放回源码；开发和测试资源必须留在自己的环境根。链接越界、文件/运行/备份目录重叠及前端静态目录暴露私有资源都会报错。备份执行与文件删除保护共享同一个目录解析函数。

兼容入口：只在daily、未明确指定HOME或配置文件、且源码目录存在旧配置/数据库/发布指针时识别旧布局，保持原相对路径语义，并在启动器提示。旧数据不会自动搬迁。日常启动器按当前源码构建和选择运行副本。旧发布清单只可用于核对当时的部署记录。

开发命令在加载应用前移除继承的日常路径、会话和常见API凭证变量。Vite转发前核对health中的development身份及预期数据库路径，不匹配返回503。测试不复制日常OCR缓存或前端dist；需要OCR夹具时放在本机packages/server/test/fixtures/tessdata。模型凭证与外部绑定由当前环境数据库保存；空环境不导入日常设置。

应用 tsconfig 只检查应用源码，私有测试可另用原 tsconfig.test.json；共享测试直接通过 Node 24 的隔离入口执行。

## 4. 提交与推送检查

```powershell
npm run repo:check
git status --short
git add -- <本批明确文件>
npm run repo:check:staged
git diff --cached --stat
git commit -m "chore(repo): 隔离源码与本机资料"
git push
```

按任务授权提交并推送准确范围。钩子可用 `npm run repo:hooks` 安装。

- pre-commit检查实际暂存内容，拒绝本机专用路径、未知文件类型、链接及常见凭证模式；不会把命中值写入日志。
- pre-push检查本次新增的全部提交，防止中间提交带数据、末次删除后又连历史一起上传。
- 普通检查使用共享工作文件；本机私有文件只按路径排除，不读取其正文。
- 钩子依赖本机安装和Git客户端，不是GitHub服务器端强制规则；规则无法识别所有业务敏感正文。

新增可分享工具时，需同时审查策略和.gitignore。不要为方便把整个work、测试目录或本机配置放开。

## 5. 已跟踪文件与旧历史

忽略规则仅作用于未跟踪文件；取消跟踪须保留本地文件并核对。历史提交中的内容按单独授权处理。

这不等于清除了旧提交。当前远端旧提交中的业务资料仍需另行授权后处理历史，不能靠普通删除提交消除。推送钩子会阻止向全新空远端发送仍包含这些资料的旧历史。

## 6. 文档与打包

文档生成器仅索引允许共享的文档和源码，不收集私有测试、历史报告及运行快照的内容或摘要。当前文档保留的历史参考链接被标记为本机证据，在新电脑可能不可用，不作仓库链接失败。

默认 `npm run pack` 包含共享源码、配置样例与合成回归。排除真实资料、私有用例及实际运行现场。显式完整备份可能包含凭证，仅供私下保管。

## 7. 验证

`npm run test:repository` 在临时 Git 仓库验证暂存、共同祖先、空远端及中间提交的保护，`npm run test:isolation` 验证数据根和共享路径。

历史专项仍可通过其本机入口独立执行。

源码运行缓存位于检出根 .local/source-builds 下的环境分区（test 在隔离根内）；只复制共享源码和锁文件、准备独立依赖与web，不复制配置或业务资料。WORKBENCH_LAYOUT_ROOT由启动器指定原检出根以保持旧配置语义，健康身份来自实际副本；不能把该变量当作任意绕过路径守卫的配置。项目及用户npm配置由npm 11子进程在原检出根原位读取，不复制到准备或完成副本，不将配置值放入命令参数或自建凭据文件；保留相对cache/cafile路径与npm认证过滤，不读取业务或模型配置。旧版本已中断的准备目录不会被本修复自动删除；若其中已留有.npmrc，需在确认无活动准备进程后仅处理那份复制配置，不删除原仓库/用户配置或业务数据。缓存及source-current、SOURCE_BUILD均是本机运行记录，不上传Git。
