# 第三轮：业务页面与文书生成体验

日期：2026-10-15。浏览器操作由代理执行，使用本机隔离业务实例和匿名验证模板；不代表用户已确认正式业务内容。

## 已改变的操作流程

日常入口现在为：选择工作类型 → 选择工作期次 → 填写业务内容 → 选择或调整适用模板 → 自动带入字段 → 预览修改 → 保存草稿或定稿。单次工作和项目也能在工作内直接生成文书。创建时可以暂不选模板，之后再选；明确的空选择不会回退成“所有模板”。

生成成果自动保存，记录当前工作、期次和模板成果类型。再次修改从已保存的变量恢复，保留旧版本；首页只显示各版本链的最新成果，旧版从版本记录查询。正文在生成、保存模板选择前自动保存；步骤或材料刷新时保留正在编辑的正文。

模板选择允许指定对应的本期成果要求。生成草稿自动关联并记录已提供；用户确认定稿后自动更新为已核对。相同名称的要求也可自动匹配，不需要重新上传或逐份绑定生成件。签章、合同、现场证明等真实外部材料仍保留人工核对，不因文件存在就推断已经签章或完成业务。

首页优先显示工作名称、类型、当前阶段/期次、待办、业务内容、模板及生成成果。目录、高级排期、材料核对、导入历史成果、工作整体结束和办理记录下沉到次级区域。项目的阶段、材料、档案及交付管理继续复用原有能力，没有新增工作流引擎。

## 混用原因及修复

1. `listTemplates` 原来将 `work_type_id IS NULL` 的所有未分类模板视作通用模板；实际库中存在工程验收等未分类模板，因而会出现在不适用的工作中。现在只自动提供本类型或明确标记共享的模板；未分类不等于通用。生成字段、预览、保存也检查工作类型和阶段归属，直接调用接口不能绕过。
2. `WorkExecution` 无条件提供供应商交付表单。现在按领域提供办理入口，行政后端也拒绝新增供应商交付事项。
3. 新建窗口切换领域时可能短暂保留上一类型和模板选择。现在同步清理选择、验证选定类型属于当前领域，并在 API hook 中按请求路径隔离返回数据。
4. `PeriodExecution` 原来对所有期次都展示多次检查和季度汇报来源文案。现在检查专用内容只出现在检查工作中，跨工作季度来源选择只出现在季度汇报；其他类型使用自己的步骤和按需材料入口。

只读审查实际运行库时，存量软件项目的阶段模板归属正确，未发现跨类型阶段实例；修复没有把正常历史阶段重新实例化或覆盖。

## 四类文件

- 模板：模板库中的生成规则和 Office 模板，按类型选择。
- 来源资料：已有业务记录和参考依据；生成时按本次选择引用，不默认把目录全部输入模型。用户明确选择的跨工作来源期次保留原有汇总能力。
- 生成成果：自动归属工作/期次/模板，独立草稿、定稿和版本链。
- 外部证明：上传时记录文件用途，合同、签章件、供应商资料及必要材料在次级区核对。

新增独立的只读参考目录：浏览文件及子目录、按需查看原件，不扫描纳管、不把该目录设为输出位置、不自动输入 AI。高级可写输出目录仍是单独配置。现有业务原件没有被修改或搬动。
