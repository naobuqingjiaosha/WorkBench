# AI 辅助材料生成改造任务书

日期：2026-10-21。版本：1.0。面向：接手修改代码的 Codex。

状态更新：2026-10-21源码候选已实施，20项隔离自动场景、全量回归及实际Excel文件检查已执行；后经用户授权按28文件独立包发布到日常8787，保留基础修复并排除工作记录及其他候选；真实模型与Office桌面分页仍未验收，详见[实施报告43](43-AI辅助材料生成实施与验证-2026-10-21.md)。以下为原任务要求。调研依据见[报告40](40-同类工作台与AI协同调研-2026-10-21.md)。本文件是本次变更的主要需求依据；较早材料中与之冲突的报送、强制办结和空白新建要求以本文件为准。与本次无关的业务约束继续保留。

## 1. 用户已经确定的方向

- 工作台帮助制作材料，不管理是否报送。不要再要求登记报送日期、上传回执或点击已报送。
- AI 要参与整个材料准备过程：找相关历史、带入内容、建议检查主题、起草文字、按用户要求修改、选择适用模板并生成文件。
- 新建本月检查时，系统主动参考上个月，尽量少让用户从空白开始填写。
- 用户不知道检查什么时，允许助手主动构思和给出候选草稿，用户再改。
- 普通零散工作继续采用工作记录，不恢复通用单次办理流程。

本轮交付月检完整能力，并建设可供其他材料页面复用的上下文与草稿接口。其他业务仅做取消报送管理所必需的调整和相关回归，不承诺在本轮重写所有业务。不得以“后续再接入AI”为由只交付复制上月按钮。

## 2. 目标体验与操作成本

正常使用路径：

1. 用户进入某项工作的本月，点击“新建检查记录”，或告诉助手“帮我准备本月检查材料”。
2. 页面立即展示可复用的历史信息。存在合适来源时默认选好，并注明参考月份；本地历史检索不依赖模型成功。
3. 在模型服务和资料使用范围已获允许时，自动补充检查主题、内容及写法建议。用户可边看边改，不必等待整段聊天结束。
4. 用户直接修改表单或说“换成设备调试方面”“保留项目，只改检查内容”“简短一些”；助手只改相关草稿。
5. 用户可以“采用并生成文件”，也可以“下载待确认草稿”。生成结果直接提供预览、下载、继续修改入口。

不设置报送页，不要求生成后再定稿、再报送、再完成本期才能拿到文件。历史定稿版本仍保留，用户可自愿保留确认版本，但不能成为重复的强制办理动作。

采用确认集中在一个可编辑预览里完成，不逐字段弹窗。表单中的空缺或有冲突信息集中提示，不逐题盘问。

## 3. 取消报送管理：需要修改整个判断链

### 3.1 当前行为

- 移除新办理界面的“实际报送确认”、报送日期输入、报送回执要求，以及首页“待报送”任务。
- 当前文书生成和材料就绪判断不依赖 `reported_on`、`report_snapshot`，也不依赖仅用于证明已报送的材料项。
- 不要求“完成本期”才能下载。默认用“待起草／编辑中／文件已生成／内容变化待更新”等材料状态解释当前进展。
- “文件已生成”只表示存在归属于当前来源版本且可访问的生成件，不表示现场检查、报送或整个业务已经完成。用户选择多份文件时，显示逐份成功或失败，不把部分成功显示为全部成功。
- 用户仍可打开一个有文件的期次继续编辑；不因材料已生成就锁死后续修改。
- 若保留旧完成接口供兼容使用，只能记录适用的材料整理状态，不写入虚假的报送事实，不修改历史完成时间。具体存储方案由源码核查后确定。

### 3.2 兼容边界

- 保留旧报送字段、已存在的报送记录、旧完成记录及成果文件；可放在折叠的历史详情，只读展示，不生成新的待办。
- 不通过设置“已报送=true”、填今天日期或批量改done来绕过旧判断。
- 旧期次快照中的报送要求同样不应重新阻断当前材料制作；用明确的兼容解释处理，不能为清理文案破坏历史快照。
- 保留实际合同、签章和项目验收等已有资料及规则。取消报送管理不等于删除所有附件要求或宣布项目验收通过。
- “报告期”“报告月份”是文书内容或期次，不等于报送行为，不能全局搜索替换“报”字。模板真实标题含“报送表册”时保留原文件名称和稳定标识。
- 扫描页面、首页统计、助手工具、接口、领域判断和测试，避免只隐藏前端卡片。

## 4. 自动参考上个月

### 4.1 来源选择

默认范围为当前工作及所选月份的前一个自然月，跨年应正确处理。优先使用同一具体项目的最新有效修订，排除删除、撤回内容。

未选具体项目时，展示上月各项目／检查事项的来源候选，提供可直接编辑的推荐草稿；不得把上月多条记录无提示合并为本月一次检查，或自动全部写成已发生记录。用户可以选择一条、切换来源，或批量生成分别独立的草稿。

上月同项目有多次检查时，依据最近有效记录默认选择并显示其余候选。若当前仅有项目名称文本、没有可靠项目ID，按已有结构谨慎匹配，不能让模糊名称把不同项目自动合并。

上月没有记录时，可以参考同工作更早的最近有效记录，但必须明确真实月份。没有历史时，使用当前项目资料、适用模板和用户提供的业务背景生成建议；无关项目资料不自动混入。缺项目背景时给通用检查方向，不编造项目名称。

### 4.2 字段处理

| 字段 | 自动处理方式 |
|---|---|
| 当前月份、期次归属 | 由用户所选期次确定，不复制历史periodId |
| 项目、被检查单位 | 从匹配来源带入为可编辑候选，优先采用当前明确资料 |
| 检查主题、检查方法、检查清单 | 可参考上月并结合当前阶段改写，显示“参考上月”或“AI建议” |
| 检查人 | 可作历史候选，但不自动声明本月已经参与 |
| 实际检查日期 | 有本月明确来源才直接提取；否则留空或待确认。用户可选择拟定日期，但不得混作实际日期 |
| 检查结果、发现问题、整改完成情况 | 不把上月结论直接复制成本月事实；历史内容作为参考，AI拟写作为待确认建议 |
| 数量、金额、次数、完成率 | 已知事实由程序计算或来源提取；未知不自动编数字 |
| 定稿、报送、完成、签章、外部证明 | 不继承历史状态或证明身份 |

保留来源记录ID、来源期次、修订号及字段来源。默认简洁展示来源标签，详细内容折叠，避免把技术元数据铺满表单。

本地复制稳定字段应在无模型时仍可使用。切换来源应可撤销；已经改过的字段不得被后到的历史请求覆盖。

## 5. AI 可以主动构思和编写什么

### 5.1 应主动提供

- 根据项目类型、已知阶段、历史主题和未关闭问题，推荐检查重点，并用一句话说明依据。
- 不只重复上月措辞；可以推荐新主题、轮换重点或问题复查。没有相关制度来源时，将其标为一般建议，不冒称制度规定。
- 给出可执行的检查清单、拟采用方法、需要查看的材料和文字草稿。
- 用户只告知简短结果时，帮助整理为符合模板的自然段。
- 对结果段落可以提供条件化写法示例，例如“若已核对且未发现问题，可采用以下表述”，由用户改为实际情况或明确采用。
- 支持“换一个方向”“更简洁”“沿用上月结构”“只修改这一段”“恢复上一版”等操作。

### 5.2 草稿与实际记录

猜测可以帮助起草，但不能因为写入数据库就自动成为事实。最少区分：已有来源、历史参考、AI建议、用户输入／确认。无需设计复杂评分体系。

检查建议和不完整记录可以持久保存为草稿；未确认草稿不计入“已开展检查次数”、实际问题统计、年度累计事实或助手的已完成工作回顾。用户确认后可作为用户陈述进入适用记录，但不自动升级为外部证明。

不能为了通过现有 `saveInspection` 校验，默认填今天为实际日期、填“无问题”、填“整改完成”，或者仅把一条真实记录复制换月份。

用户不用填写所有事实也能生成待确认草稿。存在未确定的日期、结果或数字时，文件中使用明确占位或“草稿／待确认”标识；没有结果不等于正常，也不等于没有开展检查。

### 5.3 整体采用与可用文件

预览展示AI建议、空缺与来源，用户可以一次“采用并生成”，无需额外逐条审批。这个操作对预览中明确呈现且用户接受的建议记录确认；仍为空的事实不得自动填造，生成件继续作为待确认草稿。

当必要事实已明确、用户已采用相关内容且文件成功生成时，可输出正常业务文件。来源标记保存在系统中，不在正常文件正文强制加入技术标签。文档生成状态与事实确认状态分别表达，不能用“已下载”推断“已确认”。

## 6. 助手全程协同，避免独立聊天孤岛

| 使用位置 | 助手应获得的上下文 | 应提供的帮助 |
|---|---|---|
| 首页 | 用户当前选择、待编辑材料及可确定的工作月份 | 定位“本月材料”，多义时只问影响目标的最小问题 |
| 月检列表 | 当前工作、月份、历史候选 | 自动带入并起草，支持一条或分别多条草稿 |
| 记录编辑 | 当前字段、人工修改标记、来源与修订 | 改写指定字段、补建议、换主题、比较及撤销 |
| 模板选择 | 当前记录、模板适用类型和单次／汇总范围 | 默认推荐适用模板，可更改，不选错汇总范围 |
| 文件生成 | 当前草稿／记录版本、模板版本及必要变量 | 按可用信息生成；失败保留内容并给出重试入口 |
| 文件生成后 | 对应文件、来源版本和后续修改 | 展示预览下载；继续编辑生成新版本；不引导报送 |
| 下次进入 | 已保存草稿、人工修改、撤回／修订情况 | 恢复进度，不自动重跑覆盖已有草稿 |

助手和页面使用同一领域服务和草稿，不创建两套互不相通的数据。只允许结构化工具修改明确字段；模型不能自由提交SQL、任意文件路径或未知记录ID。

读取上下文必须核对工作、期次、记录归属。响应携带目标身份及基准修订，切换月份、编辑目标或来源变化后，旧响应不自动应用。用户已改字段默认保留，覆盖建议用差异呈现。

“重新生成”默认只更新指定建议；不会删除人工输入。流式展示可以逐步出现，但只有完整且校验通过的结果才允许作为一次应用操作提交。

## 7. 技术实现要求与定位入口

优先复用当前技术栈、模型配置、生成服务、来源签名、修订号、持久化、工作记录和隔离测试设施。可借鉴 CopilotKit 的共享状态和 assistant-ui 的工具卡片，不要求安装这两个项目；如引入依赖，必须说明解决了哪项现有实现难以合理解决的问题，不启用外部托管服务作为默认条件。

建议的内部步骤：范围解析→本地检索→确定性预填→模型建议→结构校验→可编辑预览→应用／保存草稿→文件生成。不要把确定性复制也全部交给模型。

定位入口如下，不是要求机械限定只能修改这些文件：

- 后端检查及汇总：`packages/server/src/domain/inspections.ts`。
- 期次状态及待办：`packages/server/src/domain/periods.ts`、`packages/server/src/domain/workflow.ts`。
- 检查与期次接口：`packages/server/src/api/routes-workflow.ts`。
- 助手及相关接口：`packages/server/src/domain/agent.ts`、`packages/server/src/api/routes-agent.ts`。
- 生成及来源校验：`packages/server/src/domain/generate.ts`、`packages/server/src/api/routes-generate.ts`，以及现有定稿和来源核对模块。
- 交互：`packages/web/src/components/InspectionRecords.tsx`、`packages/web/src/pages/Periods.tsx`、`packages/web/src/pages/GenerateModal.tsx`、`packages/web/src/pages/Agent.tsx`、`packages/web/src/pages/Dashboard.tsx`、`packages/web/src/components/WorkflowPanels.tsx`。
- 关联检查：`packages/server/test/phase4-inspections.ts`、`packages/server/test/template-collections.ts`，及现有助手、期次、生成相关测试。

现有真实记录接口强制日期和结果，不能用前端标签假装已支持草稿。选择独立草稿存储或明确草稿状态等最小可靠方案，说明对既有查询、统计、备份、恢复、删除和生成的影响。新增迁移不得预设编号038空闲，应核对现有迁移。

文件与记录关联需要覆盖草稿ID或记录ID、修订、工作、期次、模板版本；对不完整草稿提供明确生成入口，不能必须先伪造一条有效事实记录。字段名可沿用现有模型，无需照抄本文件术语建表。

后台生成失败、模型失败、保存失败应分别反馈。草稿可跨刷新恢复；重复点击、超时重试和重新进入不重复创建记录或重复计数。取消请求后不得继续覆盖表单。用户编辑优先于较早发出的模型响应。

真实资料的云端外发及付费调用遵守现有授权设置。本需求授权建设自动辅助能力，不等于本次开发可无限调用付费服务或把日常资料发送到新服务。已存在明确允许范围时不重复确认；无模型或无权限时继续提供本地复用和手工编辑，并如实显示AI建议尚未生成。

## 8. 验收矩阵

| 编号 | 场景 | 应通过的结果 |
|---|---|---|
| A01 | 本月无报送记录 | 可起草、生成、下载；首页与详情不催报送；后端不因报送阻断 |
| A02 | 旧期次有报送记录和快照 | 数据及文件保留；历史可查；不会被改写为今天或新增待报送任务 |
| A03 | 同工作上月有一条有效记录 | 自动带入适用信息并标来源；原记录内容和修订不变 |
| A04 | 一月参考上一年十二月，上月无记录 | 月份计算正确；回退更早来源时标明真实月份，不称为上月 |
| A05 | 上月有多个项目或同项目多次检查 | 候选清楚，可切换；不无提示混合，不自动增加本月事实次数 |
| A06 | 上月结果是无问题或整改完成 | 本月不自动继承为事实；结果可以为空或有明确待确认示例 |
| A07 | 用户不知道检查什么 | AI给出与已知项目背景相关的主题、方法和可改草稿；无依据不冒称制度要求 |
| A08 | 日期、结果缺失 | 可保存并恢复草稿、导出明确待确认文件；不能靠虚构值通过校验 |
| A09 | 用户给出实际结果并整体采用 | 已确认内容进入适用记录和文件；来源保持可追溯，操作不要求逐字段弹窗 |
| A10 | 未确认草稿参与月度／年度或助手汇总 | 不作为已开展事实计数；草稿预览与正式事实汇总有清楚边界 |
| A11 | 用户修改字段时旧AI请求返回 | 人工修改不被覆盖；目标或修订失效的建议不自动应用 |
| A12 | 切换工作、月份、检查记录或模板 | 草稿、历史来源、模型响应、生成结果不串范围 |
| A13 | 模型超时、无模型、格式错误、取消 | 保留本地预填与人工输入，可继续手工完成，失败不伪装成功 |
| A14 | 重复点击保存、采用、生成，刷新后重试 | 无重复事实、统计或意外覆盖；生成部分失败能逐项重试 |
| A15 | 修改已生成文件的来源内容 | 原文件保留，新版本正确；页面说明旧文件待更新，非报送待确认 |
| A16 | 从助手发起、页面继续编辑，再让助手修改 | 操作同一份草稿，可撤销指定建议；不用复制粘贴聊天内容 |
| A17 | 单次表、月度汇总、年度累计 | 正确选择范围、记录和模板；检查日期、项目及数字不混用 |
| A18 | 历史来源被更正、撤回或删除 | 恢复草稿和继续采用时识别变化；旧引用不继续当成当前事实 |
| A19 | 一次生成多份Word／Excel | 成功文件可预览下载；失败列表准确；占位、表格、分页和必要计算已检查 |
| A20 | 关联业务回归 | 项目阶段、工时算法、轻量工作记录、模板关联和历史资料未被本轮规则误改 |

流程验证使用匿名样本及隔离数据。模拟模型用于确定性接口和失败路径测试，不能证明真实写作质量。另用允许的真实模型验证至少“有历史、无历史、历史结果不适用、用户局部修改”四类样例，检查相关性、少改程度、事实混淆和上下文准确性；若无可用模型或授权，明确列为未验证，不宣称AI体验已经验收。

## 9. 实施顺序与交付边界
