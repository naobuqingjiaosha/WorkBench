## 二、业务模型

```text
业务领域 domain：行政管理 / 项目实施
  └─ 业务分类 category：安全管理、清廉工程、部门综合管理、临时工作、软件研发、系统集成等
      └─ 工作类型：执行方式、默认周期、材料、模板及专用能力
          └─ 工作实例：类型规则快照、自己适用的要求和实际资料
              ├─ 阶段执行：阶段副本、材料清单、文书要求、交付及协调事项
              ├─ 独立期次：月 / 季 / 年的材料、事实、文书和完成状态
              └─ 简单事务：可以没有阶段或期次
```

- `domain` 决定业务领域和 A/P 编号；`mode` 决定文书 / 简单事务或阶段流程，两者独立。
- `category` 是类型的业务分类，不驱动执行规则。分类使用可编辑名称，当前规模不需要新增分类管理平台。
- 类型增加周期默认、专用执行能力、规则版本号；工作保存创建时的规则快照。默认变更作用于后续新工作，已建期次保留原快照。
- 新建阶段实例复制目录名和目录分期规则。实例目录调整只作用于本工作，已有文件位置保持原记录。
- 阶段与期次都是可选执行结构。当前暂不支持“每期独立一整套阶段”；接口明确拒绝该组合，避免多期共用阶段状态。

预置安全月度、清廉季度、部门年度、临时工作、部门工时、软件研发和系统集成的起始配置。项目类型提供不同阶段骨架，具体必备材料与文书由用户按适用业务维护，不以空清单宣称完成实质合规检查。

## 三、主要功能调整

| 环节 | 当前行为 |
|---|---|
| 类型维护 | 新增重复编码返回冲突；编辑依 ID；已使用的执行方式及专用能力不能直接切换；新增类型可配置领域、分类、默认周期和材料 |
| 阶段维护 | 名称、顺序编辑不创建新阶段；编码稳定；“追加缺失阶段”只增补缺失阶段，不覆盖既有清单、目录或顺序 |
| 创建工作 | 行政类型可选择；阶段式行政、文书型项目均可创建；类型默认周期自动生效；创建失败整体回滚 |
| 周期办理 | 新入口使用独立月 / 季 / 年期次，不再使用旧“完成一下推进下一月”的模型；期次事实和文件分别保存 |
| 周期结束 | 完成单期不结束父工作；全部期次办完后可显式结束整个周期工作并归档，停止自动续期 |
| 进度 | 以已核对且实际文件有效的材料、必备文书定稿、阶段及事项完成计算；上传或勾选提供标记不能替代核对 |
| 完成与归档 | 未结束阶段、未核对材料、丢失的实际文件、缺失定稿或未完成事项会阻断；阶段不适用须写依据 |
| 实例要求 | 材料可按实例调整为必备或选备，须记录依据；阶段文书继续复用已有差异预览与确认机制 |
| 交付与协调 | 事项关联工作、可选阶段、责任方及截止日期；供应商交付、待协调事项和普通事项分别标记并参与完成检查 |
| 历史补录 | 可创建业务已结束、档案仍整理中的项目；保留实际结束日期；材料按适用阶段补录、核对、归档 |
| 已有文书 | 可将人工核对过的已有 Word / Excel 成果关联到阶段或期次及模板并导入为定稿；实际文件仍须通过定稿检查；失败保留草稿并告知 |
| 材料上传 | 修复通用上传忽略 `checklistItemId` 的问题；上传前验证工作和阶段归属，材料核对项中可以直接上传和核对 |
| 模板要求 | 必备成果和可选模板分开；未显式选为必备的同类型参考模板不会全部阻断完成 |
| 模板历史 | 字段规则修改和模板修订前保留模板二进制及映射副本；可下载旧模板及旧映射；不会追溯恢复此前已经丢失的版本 |
| 工时归属 | 运行关联工作及月度期次；禁止跨工作、跨月或已关闭期次混用；同月多个工作分别追踪 |
| 工时调整与归档 | 研发优先算法保持；逐日可人工调整并填写依据，重算生成新记录；人工核对后保存实际 XLSX 定稿，所属期次才能完成 |
| AI 资料范围 | 自动读取当前工作记录或当前期次事实及关联文件正文；排除其他期次和丢失文件，展示本次来源供人工核对 |
| 状态刷新 | 核对、上传、阶段完成及期次变更通知外层更新；工作与档案状态分别展示 |
| 回收站 | 补齐期次、工时、事项、材料文件引用的清理顺序；恢复保留归属，彻底清理不留下外键阻断 |

“收起”用于正在办理的工作；已完成工作使用“归档”。这两个操作仍复用原有可恢复归档机制。业务已结束与档案已备齐分别展示，不能用一个归档标志替代两者。

## 五、剩余限制与下一阶段

- 每期独立阶段尚未实现，目前明确阻止混用。实际出现这类业务后，再设计期次级阶段实例，不通过目录分层假装实现。
- 真实安全、清廉和项目验收材料要求仍需按本单位业务配置；预置骨架不代表适用性已经验收。
- 尚未用真实整月工时副本逐人逐日对账，也没有进行真实 Word/WPS/Excel 分页及打印验收。
- 真实本地模型的长文汇总质量仍需业务样例检验。当前自动上下文有来源数量和文本预算上限，适合人工核查的初稿，不承诺覆盖所有历史文件。
- 模板历史从本轮之后的受控修改开始保留；历史文件备份和数据库备份应配套，数据库恢复不会自动恢复所有文件。
- 扫描 PDF 直接 OCR、长期人员与项目别名档案等原有扩展项仍未实现，未纳入本轮已完成能力。
- 浏览器文件选择和真实 Office 交互验收仍待在具备相应权限的用户环境中完成。

下一阶段优先使用真实资料副本，分别配置一条月报、一条季报、一个软件项目、一个集成项目和一个部门整月工时，核对要求、来源和成品版式。无需继续增加通用引擎或专用大模块后才开始实际试用。
