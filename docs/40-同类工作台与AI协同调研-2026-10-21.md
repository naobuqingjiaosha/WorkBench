# 同类工作台与 AI 协同调研

调研日期：2026-10-21。用途：供 Codex 理解可借鉴机制，与[实施任务书41](41-AI辅助材料生成改造任务书-2026-10-21.md)配套使用。

状态：公开资料调研、部分 GitHub 文件读取及本地源码静态核查完成；未安装运行外部产品，未实施功能修改，未调用业务模型。本报告中的产品机制为资料事实，适配方案为设计建议，不能写成当前工作台已经具备。

## 1. 最新用户目标与旧方案的调整

用户在本次会话明确要求：

1. 把 GitHub 与商业产品调查保存成可供 Codex 读取的文档。
2. 工作台不需要管理是否报送，只需要帮助生成文件。
3. AI 助手全程参与：新建本月检查时自动提取上月资料，尽量少改；用户不知道检查什么时，助手主动建议并起草，用户再修改。
4. 原先调研项目不能覆盖的能力，可以继续寻找新的 GitHub 项目。

因此，之前聊天中的“定稿→报送→本期完成”实施提示词不再作为本轮目标。报告33、35、36、39中相关要求属于旧基线，应按任务书41的变更规则使用。历史报送事实保留，但不再作为当前生成文件或材料就绪的门槛。

本轮目标主线：**打开本月 → 自动参考历史 → AI 形成可编辑建议稿 → 用户少量修改或整体采用 → 生成可下载文件 → 必要时继续修改并生成新版本。**

允许 AI 帮忙构思检查主题、检查方法、检查清单、建议措施和文字草稿。实际检查日期、人员、发现问题、是否整改完成等仍需区分已知事实与待确认建议。用户可先下载带明确标识的草稿，无须先补全所有结果。

## 3. 商业软件如何制定流程

| 产品 | 配置方式 | 适合借鉴的内容 |
|---|---|---|
| 简道云 | 表单→流程节点→负责人及字段权限→提交、回退、限时等规则→启用版本 | 明确字段、操作和异常路径；流程版本与历史实例区分 |
| 明道云 | 工作表事件触发→填写、审批、分支等节点→按结果执行后续动作 | 把自动处理和人工编辑放在同一业务记录周围；审批只是其中一种能力 |
| 飞书多维表格 | 记录新增、修改、到期、定时等触发→操作与分支→运行日志 | 轻量记录、自动提醒及状态反馈；需考虑套餐运行额度 |

官方依据：[简道云流程设计](https://hc.jiandaoyun.com/doc/9049)、[流程版本](https://hc.jiandaoyun.com/doc/9058)、[明道云审批子流程](https://help.mingdao.com/workflow/node-initiate-approval-flow/)、[飞书多维表格工作流](https://www.feishu.cn/hc/zh-CN/articles/170735237222-%E4%BD%BF%E7%94%A8%E5%A4%9A%E7%BB%B4%E8%A1%A8%E6%A0%BC%E5%B7%A5%E4%BD%9C%E6%B5%81)。

应用到本项目时，配置工作应回答：这是什么业务、参考哪些资料、填写什么、生成哪些文件、哪些信息允许自动带入、来源变化如何处理。用户已取消报送管理，因此无须配置报送人、回执、报送日期和报送完成节点。

## 4. 新增 GitHub 调研：让 AI 进入实际办理页面

此前的 Memos、docassemble、AnythingLLM 能分别提供记录、按需补信息和资料检索的参考，但不足以单独说明 AI 怎样与当前表单协同。因此新增以下两个项目。

### 4.1 CopilotKit：助手与表单共享当前状态

仓库：[CopilotKit/CopilotKit](https://github.com/CopilotKit/CopilotKit)。读取了官方 README，并核对当前提交 `abc6807f35865e043c498398e3080f137ddbdad9` 下的[固定版本README](https://github.com/CopilotKit/CopilotKit/blob/abc6807f35865e043c498398e3080f137ddbdad9/README.md)。这是资料核查基点，不是建议直接安装的依赖版本。

已核实机制：

- 共享状态允许应用和助手读写同一组应用数据，界面能响应助手的修改。[Shared State](https://docs.copilotkit.ai/shared-state)
- 交互工具可以呈现表单，等待用户输入后继续；不必把每一步都变成纯聊天问答。[useHumanInTheLoop](https://docs.copilotkit.ai/reference/v2/hooks/useHumanInTheLoop)

适配建议：助手收到当前工作、月份、所选记录、表单值和修订号；生成建议直接出现在检查表单中。用户说“换一个检查重点”“只改检查内容”“按上月格式简短一点”，助手修改指定草稿字段。应用负责校验目标和冲突，不能让模型直接写任意数据库记录。

共享状态本身不等于防止覆盖人工输入。本项目仍须实现字段修改标记、请求身份和修订校验。采用机制优先，是否引入依赖由实施者比较现有 React／Fastify 接口后决定，不自动运行官方脚手架。

### 4.2 assistant-ui：把助手操作显示成可编辑卡片

仓库：[assistant-ui/assistant-ui](https://github.com/assistant-ui/assistant-ui)。读取官方 README 及 Tool UI 文档源码，核对提交 `38d43fff71a444ba935cc46577c72550a35573d2` 下的[固定版本Tool UI文档](https://github.com/assistant-ui/assistant-ui/blob/38d43fff71a444ba935cc46577c72550a35573d2/apps/docs/content/docs/tools/tool-ui.mdx)。

已核实机制：工具调用可用自定义 React 组件显示加载、结果、错误及交互表单；现有后端工具可仅接入显示组件。官方指南还覆盖消息编辑、重新生成和建议操作。[官方指南](https://www.assistant-ui.com/docs/guides)

适配建议：在检查详情或助手中显示“已参考上月”“建议检查内容”“本次修改差异”“文件生成结果”卡片。用户可以直接编辑、采用、撤销或重试，不必复制聊天文本到多个字段。模型调用失败不能把页面写成“没有记录”。

这是一套交互组件能力，并不提供检查业务事实、项目匹配或正式文档生成规则；这些仍由本项目承担。不为加入卡片而改换全部聊天后端，也不默认启用其云端持久化服务。

## 5. 建议的 AI 办理模式

```text
当前工作、月份及表单
        ↓
本地检索上月记录／相关项目资料／用户已告知的工作情况
        ↓
可确定字段直接带入 + AI 提出检查重点和文字建议
        ↓
同一页面编辑；历史参考和建议来源可展开
        ↓
整体采用并生成，或先下载待确认草稿
        ↓
文件归属当前期次与草稿／记录版本；后续修改生成新版本
```

这一模式要减少的是用户找资料、想主题、重复打字和反复切页面的负担。不要把“用户希望AI帮忙编写”缩减为只允许检索，也不要把生成建议自动记成实际检查结果。

例如，上月有“设备到货资料检查”，本月项目仍处于实施阶段，助手可以建议“设备安装及调试记录完整性检查”，并起草检查方法和清单。没有现场结果时，可以给出标为“结果写法示例，待确认”的候选段落，但不能默认保存成“已检查且无问题”。用户确认采用后保留为用户确认内容，其来源仍可追溯。

先完成月检的“历史复用＋AI起草＋直接出文件”，同时取消工作台对报送行为的管理。共用助手可以在其他页面获得范围和快捷操作，但本轮不重写工时算法、项目阶段和所有季度业务。
