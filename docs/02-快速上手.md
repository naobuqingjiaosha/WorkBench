# 工作台 · 使用说明

> 这套系统跑在你自己电脑上，数据、文件、API Key 全在本机。

---

## 一、怎么启动

在项目目录 `D:\project\工作台` 下打开 PowerShell，执行：

```powershell
npm start
```

看到这几行就说明起来了：

```
  工作台已启动
  界面地址：http://127.0.0.1:8787
  数据目录：D:\project\工作台\data\files
```

然后用浏览器打开 **http://127.0.0.1:8787** 。

停止：在这个窗口按 `Ctrl + C`。

> 如果提示端口被占用，说明上一次的工作台还在跑（浏览器能打开就是还在跑）。
> 换端口启动：`npm run start:auto`，它会自动找一个空闲端口。

## 二、第一次使用：按顺序做三件事

### 第 1 件：配置大模型（5 分钟）

菜单「系统配置 → 模型服务商」，做两件事：

1. 在你的服务商那一行点 **配置**，把 **API Key** 粘进去，保存。
2. 点 **测试连接**。看到绿色的"连接成功"就对了。

然后往下到「模型档案」，确认「文书写作」这一行选好了服务商和模型名（例如 `deepseek-chat`），点 **试调用** 验证一次真实对话。

预置好了六家服务商，直接用就行：

| 服务商 | Base URL | 常用模型 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat`、`deepseek-reasoner` |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`、`qwen-max` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` |
| 月之暗面 | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| OpenAI 兼容 | 自己填（中转站、自建服务） | 按服务商说明 |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:14b`，不用 Key |

**不配也能用**：手工填内容、管理流程清单、归档文件都正常工作，只是不能让模型帮你写。

### 第 2 件：把你的模板传上来

菜单「模板库 → 上传模板」。

系统里已经有 **2 个示例模板**，建议先用 Word 打开看看它们长什么样：

- `data/files/_模板库/示例_月度安全检查记录表.docx`（行政管理）
- `data/files/_模板库/示例_设备开箱验收记录表.docx`（项目实施）

**改造你自己的模板只需要一步**：把每次会变的内容换成 `{变量名}`。

| 原来写的 | 改成 |
|---|---|
| 某某单位 | `{单位名称}` |
| 2026年3月 | `{检查月份}` |
| 张工 | `{检查人}` |
| 2026年3月15日 | `{检查日期}` |

上传后系统会自动把变量扫出来，你可以给每个变量补上中文标签和填写提示。
详细规则见 `docs/03-模板制作指南.md`。

### 第 3 件：建一个工作台

菜单「我的工作台 → 新建工作台」，选工作类型（行政管理 / 项目实施），填个名字就行。

创建后系统自动做三件事：

1. 在数据目录建好项目文件夹，按阶段分子目录；
2. 把每个阶段的**材料清单**生成为可勾选的待办；
3. 把每个阶段的**必拍影像清单**生成为卡片，没拍够张数会标红。

## 三、日常怎么用

### 场景 A：每月一次的安全检查表

1. 「我的工作台 → 新建工作台」，类型选行政管理，名称写「2026年3月安全检查」。
2. 「生成文书」→ 模板选「月度安全检查记录表」→ 工作台选刚建的那个。
3. 系统自动带出「检查人」「检查月份」「检查日期」等项目信息。
4. 「本次特别要求」里写这次的具体情况，例如：
   > 检查了办公楼一至三层，消火栓压力正常，应急照明抽查 6 处均可用；三层配电箱前有杂物堆放，已现场整改。结论：未发现重大隐患。
5. 点「让大模型补全」，等几秒，逐项核对。
6. 点「下载预览」打开 Word 看排版，满意后点「保存成文件」。

生成的文件落在：`data/files/工作台/2026-A-001-2026年3月安全检查/_生成文书/`

### 场景 B：项目到货开箱

1. 建工作台（类型选项目实施），系统自动生成 6 个阶段。
2. 打开「影像证据」页 → 找到「开箱前外包装」卡片 → 点「上传照片」→ 拍完直接传。
3. 卡片上会显示 `2/2 张` 变成绿色；不够张数的显示红色并提示还缺几张。
4. 照片自动按规范命名并存到 `项目/阶段/_影像证据/`，同时记录拍摄时间（读 EXIF）。
5. 材料清单里勾掉「到货通知/送货单」「装箱单」等已备齐的项。
6. 到「生成文书」用「设备开箱验收记录表」生成记录表，把影像留存情况也写进去。

### 场景 C：找以前的东西

菜单「文件与检索」，输入关键词，例如 `验收 资料`、`应急照明`、`开箱`。

它检索的是**文件正文内容**，不只是文件名——合同 PDF 里的条款、Word 里的段落都能搜到。

### 场景 D：让纸质档案、扫描件也能被搜到（OCR）

默认是关闭的，建议开一次就不管了：

1. 菜单「系统配置 → 扫描件 OCR」，勾上 **启用 OCR**。
2. 点 **下载语言包**（约 6MB，只需要下载一次，之后完全离线可用）。
3. 点 **扫描历史文件**，把之前上传的图片和扫描件补上识别。

之后每次上传照片或扫描件，系统会自动排队识别，识别出的文字进入全文检索。
也就是说：**你把纸质档案拍张照传上来，以后搜里面的字就能搜到。**

打开「文件与检索 → 详情」，能看到每个文件识别出了什么、置信度多少，识别不准可以点「重新识别」。

> 两个限制要清楚：
> - 只能识别**图片**（PNG / JPG / BMP / TIFF / WebP）。扫描版 PDF 请先用扫描软件导出成图片，或直接用手机拍。
> - 识别质量取决于图片清晰度：摆正、光线均匀、分辨率高，识别率就高。

### 场景 E：让资料"能被提问"（知识库语义检索）

「文件与检索」是按关键词找文件；「知识库」是按**意思**找内容，还能直接提问。

**开启步骤：**

1. 「系统配置 → 模型档案」，给**向量化**这一行选一个服务商和 embedding 模型：
   - 通义千问：`text-embedding-v3`
   - 智谱：`embedding-3`
   - 本地 Ollama：`bge-m3`（不花钱，需自己拉模型）
2. 把制度、规范、标准合同、验收标准等资料放进数据目录的 `_规范库` 文件夹
   （在「文件与检索」里用「上传文件」也可以，选类别「原始资料」）。
3. 打开「知识库」，点 **导入全部文件**。系统自动做：抽取文字 → 切成片段 → 调用向量化 → 建立语义索引。
4. 之后就能两种用法：
   - **检索**：例如搜「开箱要拍什么」，能命中讲「影像资料留存」的那一段（纯关键词搜是搜不到的）
   - **问它**：把检索到的原文交给大模型总结成答案，并标注每条结论来自哪份资料的第几段

**要注意的三件事：**

- **向量化会花钱**：每篇文档都要调一次 embedding 接口。embedding 比对话便宜很多，但量大时留意用量（「模型调用记录」里能看）。
- **换模型要重建**：不同 embedding 模型的向量不能混用；换了模型要把文档重新向量化一遍。
- **切块是检索的最小单位**：默认 500 字一块、在段落和句子边界断开。所以问问题时，答案最好集中在一段里。

## 四、文件都在哪

所有文件都是普通文件夹里的普通 Office 文件，直接用资源管理器打开就行：

```
D:\project\工作台\data\files\
├─ _模板库\           你上传的 Word/Excel 模板
├─ _规范库\           制度、规范、参考文件（放这里便于检索）
├─ _待归档\           不归属任何项目的文件
├─ _索引\             索引导出（可忽略）
└─ 工作台\
   └─ 2026-P-001-某局机房改造\
      ├─ 01_立项与准备\
      │  ├─ _影像证据\    该阶段拍的照片
      │  └─ _原始资料\    该阶段收到的资料
      ├─ 02_到货与开箱\
      ├─ ...
      └─ _生成文书\       大模型生成的成品
```

**想换到 OneDrive / 坚果云同步？** 编辑项目根目录的 `workbench.config.json`，把 `dataRoot` 改成新路径，
把原来整个 `data` 文件夹复制过去，重启程序即可。改完在「系统配置 → 系统信息」里能看到新路径。

## 五、常见问题

**问：生成的文件里还有 `{变量名}` 是什么情况？**
答：说明这个变量没填上。可能是模型没给（缺资料），也可能是你漏填了。直接在 Word 里手改，或者回填后重新生成。

**问：模板上传后提示"不可填充"？**
答：`.doc` / `.xls` 是旧版二进制格式，没法填充。用 Word/Excel 打开后"另存为" `.docx` / `.xlsx` 再上传。

**问：模板里没扫描到变量？**
答：确认你写的是英文花括号 `{变量名}`，不是中文书名号 `【变量名】` 或双花括号 `{{变量名}}`。
如果你的模板已经用了别的写法，告诉我，我给扫描器加规则。

**问：模型老是说"【待补：XXX】"？**
答：这是设计如此——它不会编造数字和事实。补充资料就行：把合同、纪要上传到工作台，然后在生成页勾选「参考资料」。

**问：怎么控制花钱？**
答：「系统配置 → 模型调用记录」能看到每次调用的耗时和 token 用量，按用途汇总。清空记录不影响使用。

**问：OCR 要另外装 Tesseract 吗？**
答：不用。识别引擎是内置的 WASM 版本，装在程序自己身上；只需要下载一次语言包（存在 `data/runtime/tessdata`），之后离线可用、不花钱、不上传任何文件。

**问：为什么扫描的 PDF 识别不了？**
答：本机 OCR 引擎读不了 PDF 的内部格式。解决办法：用扫描软件把 PDF 每页导出成 JPG/PNG 再上传，或者直接用手机拍。识别质量其实比扫描件更好。

**问：想改流程（加一个阶段 / 改材料清单）？**
答：菜单「流程规范」。改了之后**新建**的工作台按新流程走；已经在跑的工作台不受影响。

## 六、给程序加东西 / 排错

```powershell
npm run build        # 改过前端代码后重新构建界面
npm run db:init      # 看数据库状态：工作类型、阶段、服务商、配置项
npm run samples      # 重新生成两个示例模板
npm run test         # 纯函数单元测试（不需要启动服务），67 项
npm run test:e2e     # 核心链路端到端自检，35 项（需服务已启动）
npm run test:ocr     # OCR 链路自检，18 项（需服务已启动）
npm run test:kb      # 知识库语义检索自检，35 项（需服务已启动，会本机起假 embedding 接口）
npm run test:all     # 上面四套一起跑
npm run reset        # 清空业务数据恢复初始状态
npm run reset -- --providers   # 连模型接入配置一起复原（会清空已填的 API Key）
npm run typecheck    # TypeScript 类型检查（后端）
```

后端日志直接打在启动窗口里。数据库使用 WAL；运行时不要只复制 `workbench.db`。停止服务后执行 `npm run pack -- --with-runtime-state`，同时备份数据库、实际文件目录及配置。
