# 目录绑定方案（实施契约）

> 目标：让每个工作台**直接在它自己的文件夹里工作**——安全工作在 `工作\2.安全`，某个项目在它自己的项目文件夹，清廉工程在 `工作\11.清廉工程`。
>
> 本文件是实施的**唯一契约**：并行改动都以它为准。已确认的七条决定见 §1。

---

## §1 已确认的决定（用户 2026-10-01）

1. **工作台级绑定是主粒度**：安全工作绑 `工作\2.安全`，清廉工程绑 `工作\11.清廉工程`，以此类推。
2. **项目类**：`1.项目\...` 下**每个具体项目各绑一个文件夹**（不是绑 `1.项目` 这个大目录）。
3. **知识库**：制度类**汇总成一个文件夹**（如 `工作\3.制度`）绑为**只读来源**。本阶段**只做框架**（登记来源、显示文件数），**不做内容抽取**——等工作台侧没问题了再抽取。
4. **模板**：仍由用户自己上传指定（沿用现有 `_模板库` 流程），**不**从 iCloud 自动绑定。
5. **阶段内部按期次分目录**：要做（`2025年1月`、`202601`、`2025年` 这类）。
6. **排除其它 AI 工具产物**：默认忽略 `.workbuddy` 等（点开头目录 + 可配置名单）。
7. **先搭框架**：知识库只搭框架不抽数据。

## §2 数据模型（迁移 `010_folder_binding.sql`）

```sql
ALTER TABLE workbench ADD COLUMN external_root TEXT;      -- 绑定后的外部绝对路径；NULL = 仍用 dataRoot
ALTER TABLE artifact  ADD COLUMN root_kind TEXT NOT NULL DEFAULT 'data';  -- 'data' | 'external'
CREATE INDEX IF NOT EXISTS idx_artifact_root_kind ON artifact(root_kind);

-- 知识库来源目录（本阶段只登记，不抽取）
CREATE TABLE IF NOT EXISTS kb_source (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  path        TEXT NOT NULL UNIQUE,   -- 绝对路径（realpath 规范化后）
  label       TEXT,                   -- 显示名，缺省取末段目录名
  enabled     INTEGER NOT NULL DEFAULT 1,
  created_at  TEXT NOT NULL,
  last_scan_at TEXT,                  -- 上次扫描时间（只记元数据）
  file_count  INTEGER NOT NULL DEFAULT 0,
  total_bytes INTEGER NOT NULL DEFAULT 0
);

-- 期次目录规则（按阶段配置）
ALTER TABLE position_template ADD COLUMN period_dir TEXT;   -- NULL/'' = 不按期次分目录
                                                            -- 'month' | 'quarter' | 'year' 或自定义格式串
```

**`artifact.file_rel` 语义**：`root_kind='data'` 时相对 `DATA_ROOT`（存量数据零影响，默认值即此）；
`root_kind='external'` 时**相对该工作台的 `external_root`**。绝对路径不落库，由 `external_root + file_rel` 现算。

## §3 路径策略（核心改造）

现有：每个读写点都 `resolveInside(DATA_ROOT, rel)`。改成**允许根白名单**：

```ts
// core/paths.ts 新增
export function setBoundRoots(roots: string[]): void;          // 由启动/绑定变更时刷新
export function isInsideRoot(root: string, abs: string): boolean;   // 用 relative()，不用字符串前缀
export function resolveInAnyRoot(absOrRel: string): string;    // 命中任一允许根才放行，否则抛越界
export function rootKindOf(abs: string): 'data' | 'external';
```

允许根 = `[DATA_ROOT, ...所有已绑定工作台的 external_root]`。

**必须改的调用点**（逐个替换，语义不变，只是放宽到白名单）：

| 位置 | 用途 |
|---|---|
| `core/store.ts:164/185/213/389` | 建目录、写文件、改文件、`artifactAbsPath` |
| `api/routes-files.ts:100/157/256/298` | 上传落盘、影像落盘、缺失统计、导入目录 |
| `domain/generate.ts:451` | 出文书输出目录 |
| `domain/service.ts:737/742/745/1295` | 删工作台、校验附件、扫目录 |
| `core/checklist.ts:6` | 影像张数（另加"云端未下载"状态，见 §6） |
| `index.ts:118` | `/files/*` 兼容下载 |

**绑定时规范化**：`realpathSync` 落成规范路径再入库；拒绝：非绝对路径、不存在、`DATA_ROOT` 内部、盘根（`D:\`）、
平台自己的 `_模板库`/`_规范库`/`_待归档` 等根目录。

## §4 目录与落盘约定（用户 2026-10-01 修订：**默认就地生成**）

**原则：文件直接落在"它本该在的地方"，不集中到一个 outputs 目录**——否则用户还得手工搬一遍。

三种输出位置模式（按工作台配置，字段 `workbench.output_mode`；界面在工作台详情的「资料目录」卡片里切换，
接口 `PUT /api/workbenches/:id/output-mode`）：

| 模式 | 生成文书 | 影像证据 | 原始资料 | 用途 |
|---|---|---|---|---|
| **`inline`（默认）** | `<阶段目录>\<期次>\` | `<阶段目录>\<期次>\照片\` | `<阶段目录>\<期次>\` | 正式使用：直接就位 |
| `subdir` | `<阶段目录>\<期次>\_生成文书\` | `<阶段目录>\<期次>\_影像证据\` | `<阶段目录>\<期次>\_原始资料\` | 想让平台文件与自己的文件一眼分开时 |
| `custom` | `<自定义目录>\` | 同左 | 同左 | 自定义一个统一目录（**必须在本工作台根之内**，见下） |

- **`custom` 的目录必须落在「本工作台根」之内**（绑定后 = 绑定根 `external_root`；未绑定 = `DATA_ROOT\<folder_path>`），
  否则**当场拒绝保存**（`domain/service.ts` 的 `setWorkbenchOutputMode` → `customOutputDirAbs` 抛中文错误）。
  这不是洁癖：`artifact.file_rel` 是相对**工作台根**存的、绝对路径不落库，下载 / 预览 / OCR 全靠
  「工作台根 + file_rel」现算；输出目录跑到根外面，入库那一刻看着没问题，之后这份文件就再也定位不到
  （点下载会说"文件已不在磁盘上"）。所以初期测试用的 outputs 文件夹要形如 **`<绑定根>\_outputs`**，
  而不是任意路径（写成 `D:\project\工作台\.tmp\outputs` 这类根外路径是**错的**，会被后端拒掉）。
- **未绑定的工作台保持改造前的落点**（§9 S1「不绑定的工作台行为与现在完全一致」），
  即 `inline` / `subdir` 只对**绑定型**工作台生效：
  - 文书 → `DATA_ROOT\<folder_path>\_生成文书\`（阶段能解析出来时再套一层期次末段 / 阶段目录名）
  - 影像 → `DATA_ROOT\<folder_path>\_影像证据\<阶段名>\`
  - 资料 → `DATA_ROOT\<folder_path>\_原始资料\`

  界面在**未绑定时把三种模式的选择一律禁用**，依据就在这里：`inline` / `subdir` 的落点是相对绑定根算的，
  没有绑定根就没有"文件本该在的地方"，选了也不生效（未绑定工作台永远走上面那套老落点）。
  后端本身允许未绑定的 `custom`（只要落在 `DATA_ROOT\<folder_path>` 之内，实测通过），
  但那个目录在平台自己的数据目录里、用户既看不见也管不着，界面因此不给他切 —— 先绑资料目录再选才是正路。
  （一句话：禁用是**界面**的取舍，不是后端的限制；后端只认"必须在本工作台根之内"这一条。）
- **绑定了但没有阶段**（如文书驱动的工作台，或阶段还没建）：`inline` 落**绑定根本身**；
  `subdir` 落绑定根下的 `_生成文书` / `_影像证据` / `_原始资料` 三个目录。
- 默认 `inline` 的落点与用户既有习惯一致：他的目录里本来就有 `照片\` 子目录（如 `2.安全\4.安全活动\…\照片`、`11.清廉工程\2-组织与教育\三季度\照片`），文件也本来就是直接放在事项/期次目录里。
- 不启用期次时（`period_dir` 为空）落点退化为 `<阶段目录>\`（`inline`）或 `<阶段目录>\_生成文书\` 等（`subdir`）。
- 平台**不**再默认创建 `_生成文书`/`_影像证据`/`_原始资料` 三个目录；`subdir` 模式下才创建，名称可配置。
- **平台生成的文件靠数据库 `artifact` 记录识别**（不靠目录名/前缀），所以"就地混放"也是安全的：删除时只删登记过的文件。

## §5 期次目录（决定 5）

- 触发条件：工作台是周期工作（`recurrence != 'once'`）**且**该阶段配置了 `period_dir`。
- 期次字符串按 `recurrence` 生成，取**当前欠办那一期**（`schedule_due_date`，回退 `last_done_period`，再回退今天）：

| recurrence | 默认目录名 | 例 |
|---|---|---|
| monthly | `YYYY年M月` | `2026年10月` |
| quarterly | `YYYY年第N季度` | `2026年第4季度` |
| yearly | `YYYY年` | `2026年` |

- 自定义格式串支持 `{yyyy}`/`{m}`/`{mm}`/`{q}`（例如 `{yyyy}{mm}` → `202610`）。
- **期次目录用 A 型：两级 `<年>\<月>`**，默认格式串 `{yyyy}\{mm}月` → `2026\10月`。
  校验规则、越界防护与"为什么允许多级"见 **§12.3**。
- 落盘时目录不存在则创建；**已存在就复用**（用户手建的 `2025年1月` 直接命中）。
- 期次目录名必须在界面可见（工作台详情里显示"当前期次目录"），避免用户找不到文件。

---

## §6 iCloud 按需文件

- 全部文件/目录都带 `ReparsePoint`（云端占位）。**只读元数据不触发下载**（实测 4264 个文件扫描 1 秒）。
- 三种状态要区分：**本地 / 云端未下载 / 真的丢了**。影像张数不能把"未下载"算成"缺失"（现在 `checklist.ts:6` 用 `existsSync`，会静默归零）。
- 需要读内容时（抽文字、算 sha256、看图）才触发下载：要**排队 + 进度 + 超时**，不在扫描阶段做（决定 7 的"先搭框架"）。

## §7 安全阀（不做会出大事）

1. **删除绑定型工作台**：绝不 `rmSync` 绑定根本身。只删「平台登记过的 artifact 文件」+「平台自己的 `_` 子目录」；用户原有文件与文件夹**一个都不碰**。
   删除对话框给选项：**只删平台记录（保留文件，默认）** / 连平台生成的文书影像一起删。
2. **解绑**：只改数据库（`external_root = NULL`），不动任何文件。
3. **`pruneEmptyDirs` 必须停在绑定根**，不能往上收。
4. **绑定目录消失/改名**：明确报错（"绑定的目录不在了：<路径>"），不要抛路径越界。
5. **扫描与纳管一律原地登记**（复用 `registerExistingFile`），**绝不复制**（否则又出 `_v2` 副本）。
6. **排除规则**：默认忽略 `.` 开头目录、`tmp`、`output`、`node_modules`；名单可配置。

## §8 接口与界面

**接口**
```
GET    /api/folders/subdirs?path=<abs>        列某目录的子目录（给阶段/绑定选择用）
POST   /api/workbenches/:id/bind-folder       { path }  绑定
DELETE /api/workbenches/:id/bind-folder       解绑（不动文件）
GET    /api/workbenches/:id/bound-folder      当前绑定 + 是否存在 + 文件数
PUT    /api/workbenches/:id/output-mode       { mode, customDir? } 切换输出位置（§4；customDir 必须在本工作台根之内）
GET    /api/kb/sources                        知识库来源列表（只列文件数，本阶段不抽取）
POST   /api/kb/sources                        { path, label }
DELETE /api/kb/sources/:id
POST   /api/kb/sources/:id/scan               只统计元数据（file_count/total_bytes）
```

**界面（分两步）**
- 第一步（本阶段）：工作台详情加「资料目录」行 → 绑定/解绑/在资源管理器中打开/显示文件数；流程规范的阶段加「目录名」（从绑定根选）+「按期次分目录」开关；知识库加「来源目录」卡片（只显示路径与文件数）。
- 第二步（工作台侧确认无误后）：知识库内容抽取、检索接入、云端未下载状态与"一键下载"。

## §9 分步实施与验收

**S1 路径白名单 + 绑定存储 + 落盘**
验收（**按 §11：绑定根用本地临时目录**，例如 `D:\project\工作台\.tmp\bind-test\`，绝不用真实 iCloud 目录）：
绑临时目录 → 建阶段 `1.安全生产例会`（该目录预先手工建好）→ 上传一张照片 → 文件**出现在** `<临时根>\1.安全生产例会\`（`inline` 模式）；`artifact.root_kind='external'`；不绑定的工作台行为与现在完全一致；验证完删除临时目录。

**S2 阶段目录选择 + 期次目录**
验收：临时根下预置 `2025年1月`、`2025年2月` 两个目录 → 阶段选 `1.安全生产例会`、开 `period_dir=month` → 当期文件落到 `1.安全生产例会\2026年10月\`；把 `schedule_due_date` 改成 2025-01-10 → 文件落到**已存在的** `2025年1月\`（复用而非新建）。

**S3 删除/解绑安全阀 + 排除规则**
验收：临时根里预置若干"用户自己的文件"并记录哈希 → 删绑定型工作台 → 用户文件**一个不少**、哈希一致；解绑 → 文件全在；根目录下放一个 `.workbuddy\` 与 `tmp\` → 扫描不入库。

**S4 知识库来源框架（不抽内容）**
验收：绑 `工作\3.制度` → 列表显示路径与文件数；不产生任何 `kb_document`、不下载内容。

**S5 界面收尾**：绑定入口、资源管理器打开、当前期次目录显示、云端状态显示。

## §10 阶段目录方案（待用户确认后再实现细节）

**要解决的问题**：用户目录里阶段目录**已经存在且有自己的命名**——`1.安全生产例会`、`3.安全培训`、`0.成立项目部的通知`、`1-制度依据`、`4.合同`。如果让用户手打，错一个字就会新建一个空目录、文件落到别处，而"文件到底去哪了"是最难排查的一类问题。

**做法：从已有目录里选，绝不猜。**

1. **目录名的三个来源，优先级从高到低**：
   - ① **用户显式选定的已有子目录**（界面下拉，选项来自 `GET /api/folders/subdirs?path=<绑定根>`，每个选项显示"名称 + 该目录现有文件数"）；选中后把**精确目录名**存进 `position_template.folder_name`。
   - ② **用户显式新建**（填一个名字，平台创建；默认建议名 `NN.阶段名`，`NN` 为阶段序号，与用户既有 `1.`/`2.` 风格一致）。
   - ③ **未配置时的回退**：按现有默认 `NN_阶段名` 建在工作台根下（即"没绑定的工作台"和"绑了但阶段没配目录"两种情况行为一致）。

2. **不做模糊匹配**。理由：`1.安全生产例会` 与 `安全生产例会` 与 `例会` 都可能存在；猜错比让用户点一下更糟。下拉里给文件数提示，用户一眼能认出来。

3. **阶段序号与目录名解耦**：阶段顺序仍由 `position_template.seq` 决定；目录名只是"文件放哪"。用户可以出现"阶段 3 的目录是 `1.安全生产例会`"这种次序不一致——按用户目录为准。

4. **期次目录叠加在阶段目录之下**（§5）：`<阶段目录>\<期次>\`。已存在的期次目录（如 `2025年1月`）**按精确名复用**，不新建。

5. **界面显示**：工作台详情里每个阶段卡片显示**实际绝对路径**与**当前期次目录名**，并给「在资源管理器中打开」按钮——用户永远能知道文件在哪，这比任何日志都管用。

6. **一个阶段一个目录**（1:1）。不支持一个阶段的文件分散到多个目录；如果出现这种情况，请拆成两个阶段。

7. **绑定根本身不建任何目录**（除非用户选定了阶段目录或启用期次）。避免一绑定就在他干净的目录里多出几个空文件夹。

## §11 开发期约束（用户 2026-10-01 明确要求）

1. **开发与测试期间，绝不写入、移动、删除用户 iCloud 工作目录里的任何文件。**
   - 所有端到端验证使用**本地临时目录**做"绑定根"（例如 `D:\project\工作台\.tmp\bind-test\`），验证完删除。
   - **不做**"绑真实 `2.安全` 然后上传一张照片"这种测试。
2. **只改平台自身**（代码、平台自己的数据库与 `data/`）。用户的 iCloud 目录在首次真实绑定前保持零改动。
3. 第一次对他的真实目录做**只读**操作（列子目录、统计文件数）前，也要先说一声。
4. 用户对真实目录的"第一次写入"必须是**他明确同意后**才发生，并且要能一眼看出写入了什么（§10.5 的路径显示 + 写入前的确认）。

## §12 命名规范（定稿）

> **用户 2026-10-01 定稿，不再自行更改。** 本节是目录命名的唯一依据；与本节冲突的旧写法（§10 里提到的 `1-制度依据` 这类）以本节为准。
>
> **两条总纲**（先看这两条，再看细则）：
> 1. **只规范文件夹，不动文件名。** 平台不批量重命名任何文件。
> 2. **不批量改动用户已有目录的编号。** 没编号的目录一律原样保留；规范动作只在用户明确点选/确认后逐个发生，平台**不做**全盘重命名。

### §12.1 必须编号的层级：`N.名称`

**适用层级**：第 1 级工作分类、第 2 级事项/阶段。

格式为 **数字 + 一个点 + 名称**：

| 正例 | 说明 |
|---|---|
| `1.项目`、`2.安全` | 第 1 级工作分类 |
| `1.安全生产例会`、`3.安全培训`、`10.八大体系` | 第 2 级事项 / 阶段 |

**分隔符只认半角 `.`**，其余写法一律纠正（连字符 → 点）：

| 现写法 | 定稿写法 |
|---|---|
| `1-制度依据` | `1.制度依据` |
| `10-八大体系` | `10.八大体系` |
| `2-组织与教育` | `2.组织与教育` |

名称部分的约束：

- 名称内**不再用** `.` `-` `_` 作分隔；
- **禁用字符**：`\ / : * ? " < > |`；
- 首尾不留**空格**与**点**；
- **同级不重名**（Windows 大小写不敏感：`A` 与 `a` 算重名）；
- 数字位数不限（`1.` 与 `10.` 并列是允许的，不要求补零对齐）。

### §12.2 没编号的目录一律不动

`巡察资料`、`长治出差报销`、`其它`、`logo`、`刘新宇`、`第1次支委会`、`交流会`、`2025年`、`1月`…… 这些**没有编号**的目录**保持原样**：

- 平台**不**给它们补编号（`其它` → `12.其它` 是**禁止**的）；
- 平台**不**改它们的名字、不移动它们的内容；
- 整理报告里只**标注**"未编号，按要求不动"，把它列出来供人工判断，而不是当成待办项。

判据（一句话）：**目录名以「数字 + 点」开头才算"应当编号"**；以别的东西开头的，就是"没编号"，不动。

### §12.3 期次目录：A 型两级 `YYYY\MM月`

**用户选 A 型**：年份一层、月份一层。

```
<阶段目录>\2026\1月\现场照片.png
```

| 项 | 定稿 |
|---|---|
| 默认格式串 | `{yyyy}\{mm}月` |
| 渲染示例 | `2026\10月`、`2026\1月` |
| 月份前导零 | **带不带都行**（`{mm}` → `10月`，`{m}` → `1月`），按用户现有习惯 |

**校验规则（`period_dir` 入库前，`domain/service.ts` 的 `setPositionPeriodDir`）**

- **允许** `\` 作层级分隔符；`/` 一律**归一成** `\`（老写法 `{yyyy}/{mm}月` 继续可用）；
- **拒绝** `..`（任何形式的上级跳转，出现即拒）；
- **拒绝**绝对路径：盘符开头（`C:...`）、UNC（`\\server\share`）；
- **拒绝**其余非法字符：`: * ? " < > |` 与控制字符；
- 空层级与层级名 `.` 会被归一化/拒绝；
- 渲染结果再过一遍 `isSafePeriodPath`（名字层面兜底）。

**越界防护（落盘前，`domain/service.ts` 的 `positionPeriodDirAbs`）**

允许 `\` 就等于允许"多级路径"，所以拿到渲染后的期次名之后：

1. 按 `\` **逐段** `join` 到阶段目录上（一段 = 一层目录，跨平台语义一致）；
2. 用现成的 `isInsideRoot(workbenchRootAbs(wb), abs)` 确认**最终路径仍在绑定根/工作台根之内**；
3. 越界**抛明确错误**（`期次目录越界，拒绝使用：<期次名> 解析后是 <绝对路径>，不在工作台根 <根> 之内`），不静默回退。

名字层面的非法字符用 `isSafePeriodPath` 卡，路径层面的越界用 `isInsideRoot` 卡 —— 两道闸门，各管一层。

### §12.4 文件名不改

平台**只规范文件夹**：

- 用户已有的文件**一个都不改名**；
- 平台自己生成的文件靠数据库 `artifact` 记录识别（§4），因此也不需要通过改名来"标记归属";
- 整理报告只给**文件夹**的建议新名，从不给出文件的建议新名。

### §12.5 不碰平台自己的目录

以下目录**一律忽略**（既不检查命名、也不列入整理报告）：

- **下划线开头**：`_模板库`、`_规范库`、`_待归档`、`_索引`、`_归档模板`（以及一切 `_` 开头的目录）；
- **点开头**：`.workbuddy`、`.git`、`.tmp` 等（以及一切 `.` 开头的目录）。

理由：这些是平台/工具自己的产物目录，命名规则由平台定，不受 §12.1 约束。

### §12.6 不动 iCloud 原目录

- 平台**绝不**写入、移动、删除 iCloud 工作目录里的任何东西（§11 再次确认）；
- 允许对其它目录（例如 `C:\Users\Fangnan\Desktop\工作test` 这份副本）做**只读扫描**：只 `readdir` + `stat` 元数据，不写、不改名、不移动；
- 整理报告是**只读产物**：报告写在平台自己的 `docs/` 下，**不落在被扫描的目录里**；
- 真实写入只发生在**用户明确同意之后**，且**逐条**执行（见总纲第 2 条）。

### §12.7 整理报告的口径

`scripts/check-folder-names.mjs` 是只读扫描器，报告落 `docs/命名整理报告-工作test.md`：

- **扫描范围**：根的第 1 层 + 第 2 层（根的直接子目录，以及这些子目录的直接子目录）；
- **不合规判定**：① 用 `-`/`_` 作编号分隔；② 编号后缺分隔点或格式怪异（全角点 `1．x`、顿号 `1、x`、首尾空格/点）；③ 同级重名（大小写不敏感）；④ 含禁用字符；
- **逐条给出**：当前名 / 建议新名（`N.名称`）/ 是否与同级已有目录冲突 / 原因；
- **未编号目录**：只标注"未编号，按要求不动"，不产生建议新名；
- **需人工确认**的条目单列一节（名称内含 `.`/`-`/`_`、纯数字名、看起来像期次目录的 `2025年` / `1月` 等）；
- **只读保证**：脚本内**没有**任何 `rename` / `move` / `rm` / `mkdir` / `utimes` 调用；扫描前后对根目录做**快照对比**（递归目录清单 + `mtime`），不一致就报告异常；写报告前校验输出路径**不在被扫描的目录之内**。
