## 使用

在项目目录执行 `npm run build`。正常启动并刷新页面后，新迁移由启动流程应用；本轮未替用户启动真实业务实例。

1. 周期工作：从所选报告期生成及确认已上报；模板配置变化先预览差异。
2. 工时：填写 `输入姓名=模板姓名` 的已确认别名，或 `输入姓名=排除依据`。重新计算并下载核对，旧规则草稿不能直接定稿。
3. 项目：在材料核对区域查看必备文书缺项，需要调整已有阶段时预览并确认要求变化。
4. 记忆：在适用范围页面维护来源及更正历史；需要确定性冲突校验时，将“事实字段”填为模板变量名，同时填写“事实值”。生成定稿遇到冲突时选择本次值并注明实际依据。

## 仍需验收的限制

- 人员别名以模板姓名为本次确认目标，尚不是跨月份复用的永久人员 ID 档案；未知人员新增项目行仍需修改模板副本后重新导入。
- 自由文本记忆不能靠字符串比较可靠判断语义冲突，必须人工核对；只有已标注字段的事实参与确定性闸门。本次不会把全部自然语言自动解释成业务事实。
- 阶段快照冻结文书要求元数据，未冻结模板二进制文件。存量升级只能保留当时可见的绑定，不能还原此前已经删掉的历史要求；材料/影像清单沿用既有实例化副本。
- 原有定稿不会批量改状态；再次定稿或完成检查时执行新校验。旧工时运行须重新计算；原始文件和既有记录保持可查。
- PDF 考勤仍须人工核对转换；真实整月工时对账、安全/清廉报送、项目验收完整流程、Word/Excel 版式与实际模型审批操作尚未验收。审查中的主要正确性问题已修复，不能据此宣称原计划全部完成。
