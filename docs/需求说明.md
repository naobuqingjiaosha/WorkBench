# 需求说明 —— 我为什么要做「工作台」平台

> 这份文档用**我自己的口吻**写清楚：我要解决什么问题、要什么东西、边界在哪、怎么算做好了。
> 它不描述实现，只描述需求。平台里的功能取舍，都应对得上这里的某一条。

---

## 一、我在干什么

我手上同时推着多类工作：**清廉工程、安全工作、工程类与服务类项目、信息化、行政管理**。每一类都有自己的节奏：

- 一个项目要**走阶段**（立项、实施、验收、归档……），每个阶段有该交的材料、该拍的照片、该出的文书；
- 文书大多是**几十份 Word 模板**，内容来自项目信息、材料清单、检查情况；
- 我的依据是**制度**（本单位制度 + 上级法规 + 参考制度），要引用到具体条款；
- 出了事、接受检查时，我要能说清"**依据哪一份制度的哪一条**"。

这些事以前是我一个人用文件夹 + Word 手做的。

## 二、我真实遇到的痛点

1. **文件散、靠记忆找**：一个项目一个文件夹，材料、照片、生成件、扫描件混在一起；期次、年度又叠一层。
2. **出文书靠手工抄**：每次都从项目信息里复制字段到模板里，几十份模板来回换，**容易漏项、容易抄错**。
3. **制度查不到、查不准**：`3.制度` 里 **556 个文件 / 约 358MB**，同一份制度有多个版本和副本，还混着法规、参考制度、非制度文件（识别结果：制度 190 / 非制度 29 / 待确认 337）。
4. **文书和依据脱节**：正文里只能写"依据相关规定"，**说不清依据的是哪一条**，也没法核对口径对不对。
5. **怕丢、怕改坏**：
   - 误删一份文书或照片，就真没了；
   - AI 帮我改了字段，想撤回却撤不回；
   - 一份文书改了三遍，磁盘上是三个并列的 docx，**不知道哪个是最终版**；
   - 数据库只有一份，硬盘坏了就全没了。
6. **不知道为什么没做成**：上传照片、跑识别、出文书失败时，我看到的往往只是"过一会儿就断了"，**没有痕迹可查**。

## 三、我要的东西（目标）

1. **一个任务 = 一个文件夹**，平台认这个文件夹：任务直接绑定它自己的目录，平台的产物落在该落的位置，**我的 iCloud 原件只读**（平台不许改、不许移、不许删）。
2. **项目信息一处填、文书处处用**：项目信息填一次，出文书自动带出；模板里的**循环**（表格行）和**图片**也能出。
3. **制度变成可查、可引用的依据**：把制度抽成能检索的条款，出文书时能引用到"**哪份制度、哪一条**"，文书里带上可核对的出处。
4. **出文书前先自查**：引用的制度/条款不存在、同一事项两处口径冲突、填的数字与条款不一致——**拦住我，并说清哪里错了**。
5. **不丢数据**：
   - 误删能找回（回收站）；
   - AI 的改动能一键撤回；
   - 有自动备份、能一键恢复，**恢复前先备份当前数据**；
   - 同一份文书多版本并存，能标「最终版」，标了就不能被悄悄覆盖。
6. **看得见状态**：今天该干什么、哪些文书还没定稿、哪些照片还没交、平台有没有出异常。
7. **系统搭好之后，我自己能维护**：模板、制度、项目内容我自己往里加，**不需要每次都改代码**。

## 四、边界（明确不做）

- **单机自用**：不做云多租户、不做移动端、不上向量数据库（等片段上万再说）、不做复杂权限体系；
- **不替我做决定**：目录与命名按我已定的规则，**未编号的不要动**，不留对照表；
- **不碰我的 iCloud 原件**（只作为只读来源）；
- 我不需要"看起来很全"的功能，我需要**能长期用、坏了能修、我自己看得懂**的系统。

## 五、我已经定下的规则（不再讨论）

| 项 | 决定 |
|---|---|
| 目录命名 | `数字.名称`（如 `3.制度`）；**未编号的保持原样** |
| 期次目录 | A 类：`2026\1月`（年 \ 月） |
| 文件夹绑定 | 工作台级绑定；**每个项目各绑各的**；制度汇总成一个文件夹作为**只读来源** |
| 模板 | 我自己上传 |
| 平台文件名 | 沿用既有命名表，**不改用户已有文件名** |
| 对照表 | 不留 |

## 六、我怎么算它做好了

- 我能在浏览器里走完一条链：**建项目 → 绑文件夹 → 填项目信息 → 出文书（含循环/图片）→ 标最终版 → 查依据 → 看今日待办**；
- 我误删一份文书或照片，**能在回收站找回，且磁盘上的文件没被动**；
- 我让 AI 改了字段，**能一键撤回**，撤回后数据回到改动前；
- 硬盘坏了，我能**用备份一键恢复**，而且它先给当前数据做了一份备份；
- 我出一份文书时引用了**不存在的条款**，它会**拦住我并告诉我缺哪一条**；
- 我看首页就知道**今天该干什么**，不用逐个文件夹翻。

## 七、我和 AI 的分工

- **AI（开发方）**：搭系统、修缺陷、做代码审查，把能力做成"**可配置 + 可自检 + 有痕迹**"的；
- **平台内置模型**：日常干活——填内容、处理数据、出文书、核对口径；
- **我**：定规则、做决定、验收。

**关键一句**：我要的不是"帮我完善这个项目"，而是"**帮我把系统搭好**"——系统搭好了，内容我自己就能完善。

## 八、现状（截至需求梳理时）

- 15 项功能清单**全部交付**（防丢数据 4 项、自动化率 3 项、知识库依据 3 项、可靠性与体验 5 项）；
- 数据库迁移 001–021，`test:all` 272 项 / 0 失败；
- **已知未完成/未验证**：全部新界面还没人工点检；真实 `3.制度` 目录还没跑过抽取；6 个源文件损坏的模板需要我重传；代码审查报告列出了 49 条待修问题（其中 3 条 high 建议优先修）。

## 附：由此推出的"应该有什么"清单（与功能清单对应）

| 需求 | 对应能力 |
|---|---|
| 一个任务一个文件夹 | 目录绑定（工作台级 / 项目各绑各的 / 制度只读来源） |
| 项目信息一处填、文书处处用 | 项目信息与档案字段、变量映射、覆盖率看板 |
| 模板能出表格与图片 | 模板引擎 `{#循环}`、`{@图片}` |
| 制度作为依据 | 制度抽取入库、条款级检索与引用、文书↔制度双链 |
| 出文书前自查 | 口径校验（悬空引用 / 口径冲突 / 数字不符） |
| 不丢数据 | 回收站与恢复、AI 动作撤销、自动备份与一键恢复、文书版本与最终版 |
| 看得见状态 | 今日待办聚合、运行状态卡片、操作审计页、全局搜索 |
| 我自己能维护 | 设置项化（口径、备份、校验严格度）、迁移与自愈、文档与交接记录 |
