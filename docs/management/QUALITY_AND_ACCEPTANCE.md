# 质量管理与验收计划

文档ID：PM-QUALITY。版本：1.13。更新：2026-11-06。适用：需求、开发、文档、发布与实际业务验证。

沿用[开发与验收规则34](../34-产品开发与验收规则-2026-10-20.md)，按本次需求收束为执行入口。本文是项目裁剪规则，不宣称通过ISO、PMBOK或其他认证。

## 1. 完成状态必须拆开

| 层次 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 源码存在 | 代码有实现入口 | 正确、已发布或用户已用过 |
| 自动化通过 | 指定样例和版本达到断言 | 全部真实业务或所有模型表现 |
| 浏览器走查 | 某环境内任务和交互可完成 | Office分页、真实模型或日常已切换 |
| 实际文件检查 | 内容、结构、所检查的版式/公式符合结果 | 没检查的模板、打印机或资料范围 |
| 日常发布核对 | 配套版本已加载，相关数据核查满足范围 | 业务真实性、剩余质量缺口全部解决 |
| 业务验收 | 对应使用者确认具体业务结果 | 未覆盖业务、未来变更 |

单项检查使用：通过、未通过、受阻、未执行、不适用。历史证据另标日期与版本。

| 文件/删除/迁移 | DB与文件一致、失败补偿、占用、共享引用、重复执行及恢复 | 隔离副本和相关测试 |

## 3. 现有测试入口

以根package.json为权威；[源码索引](../reference/source-inventory.json)记录当前命令。测试用例、夹具与tsconfig.test.json均为本机资源，不随Git分发；新机先确认资源存在，再执行对应入口。缺少用例是未执行，不是通过。

- `npm run typecheck`：server/web类型检查。
- `npm test`：隔离契约与根脚本列出的单元、业务、稳定性、证据、工作记录、检查草稿套件。
- `npm run test:all`：npm test后再执行e2e、kb、agent、vision、ocr扩展。
- `node scripts/test-isolated.mjs --unit inspection-drafts`：指定专项示例。
- 前端构建使用[开发指南](../guides/DEVELOPMENT.md)的独立输出目录；不覆盖运行中日常dist。

定向测试并非所有套件都会被npm test包含，例如type-navigation需按影响显式选择。不要直接运行先导入业务模块再设置环境的测试文件。

## 5. 证据记录模板

每次记录：日期/执行者、PR/GOV/AC或场景编号、候选提交/源树摘要、发布包、隔离路径、数据来源与脱敏方式、命令/操作、预期、实际、原始日志/产物、结论、剩余边界。

真实模型记录额外包含模型标识、资料使用授权范围、样本固定方式、真实/模拟、失败样本和人工修改；不保存密钥。Office记录额外标注工具、文件及实际检查页/表范围。

评审者与执行者相同时标自检。未运行写“未执行”，缺工具写“受阻”，不因后续发布把未验收改为通过。

## 6. 发布与关闭门槛

本批范围明确、关键功能与失败路径验证完成、历史兼容及备份恢复有证据、相关高影响风险已控制、当前文档同步，才进入发布准备。真实未验收项需明确记录，并按授权范围决定是否发布。

发布后核对运行版本、首页与本批入口、数据变化是否符合计划；未达预期执行已审核的恢复方案。任务关闭只对应其范围，剩余事项分流至已有GOV，不能宣称整个项目终验完成。
