## 2. 顺序和责任

1. 从同一候选包核对 Git 来源、前后端与锁文件摘要、迁移集合、浏览器操作和实际文书。版本及剩余条件见[工作日志](WORK_LOG.md)。
2. 目标机用包内独立预览和一份获准副本，打开代表性工作、核对工时及台账、用目标 Office 打开结果。只有业务事实无法由资料判定时请用户决定。正式日常切换另行授权。
3. 剩余 GOV-01 的平台异常、GOV-10 的真实模型质量及 GOV-07 的实际效率，依所需平台、资料和调用条件安排。期限和投入尚未约定。

## 3. 状态维护

进展直接整合进对应 GOV 行，同一问题沿用原编号。源码提交/推送、候选校验、日常发布、业务验收分别记录。旧报告的“通过”只保留原版本和原检查范围。变更原因、证据、文件及交付结果按[文档治理](DOCUMENT_CONTROL.md)进入工作日志。
