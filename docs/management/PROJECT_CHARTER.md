# 项目章程与范围说明

文档ID：PM-CHARTER。版本：1.0。更新：2026-10-21。状态：依据既有需求整理的管理基线；不是新增立项审批或外部标准认证。

## 1. 项目定义

项目名称：工作台。定位：本机单用户行政管理与项目实施工具。核心价值是将分散资料、周期事项和重复文书组织为可找、可改、可生成、可追溯的工作过程。

项目负责人/业务决策方：使用者本人；具体姓名不作无依据填写。开发与文档维护由当前任务的执行者负责。预算、工期、正式上线总范围与服务等级未建立统一批准基线，不能从历史阶段报告反推出承诺。

## 2. 目标与成功判断

| 目标 | 可检查的成功结果 | 判断方式 |
|---|---|---|
| 减少重复录入 | 基础字段和相关历史可复用；检查记录可生成多份适用表册 | 实际任务走查及产物核对 |
| 保证事实边界 | 草稿、建议、计划、实际记录和外部证明可区分 | 反例与来源追溯 |
| 保持资料可恢复 | 数据库/文件关系一致，配套恢复可验证 | 隔离恢复演练与摘要 |
| 便于长期维护 | 需求、代码、测试、发布、知识入口明确 | 文档检查和接续任务验证 |
| 提高日常可用性 | 能找到目标、保留输入、看懂失败并取得文件 | 用户场景、问题记录；不编造节时比例 |

## 3. 范围与交付物

| 工作包 | 包含 | 核心文档/结果 |
|---|---|---|
| WP-01 需求与业务 | 业务线、对象、范围、约束和验收条件 | 产品需求、术语与场景 |
| WP-02 产品与实现 | 工作/期次、项目、材料、模板、助手、工时 | 前后端源码、迁移、适用模板 |
| WP-03 质量 | 隔离自动化、界面、实际文书、真实业务验证 | 原始结果、结论和未验收项 |
| WP-04 发布与运行 | 限定包、备份、配套前端、运行核对和恢复 | 发布清单、核查与恢复记录 |
| WP-05 知识与交接 | 当前知识、历史证据、入口和自动索引 | 本文档体系 |

不包含：云多租户、复杂组织审批、移动端、通用流程/低代码平台、自动正式报送、AI替用户证明业务完成。普通零散工作采用工作记录方向；未发布前不能承诺日常可用。

## 4. 责任分工

R表示执行，A表示最终责任/决策，C表示必要咨询。角色可由同一个人承担，但自检不能写成独立审查。

| 活动 | 用户 | 当前执行者 | 复核环节 |
|---|---|---|---|
| 业务目标、未定口径 | A | R整理事实与选项 | C |
| 方案、实现、相关测试、文档 | C（仅关键业务选择） | A/R | C |
| 真实业务与正式成果确认 | A/R | R准备可检查结果 | C |
| 候选范围、备份、技术发布准备 | A决定范围 | R | C |
| 日常切换/重要数据操作 | A提供有效授权 | R在授权内实施 | C核对 |
| 项目状态与问题维护 | C调整优先级 | A/R | C |

不因该表自动增加审批层级、派人或启动子代理。普通可逆工作在任务范围内自主完成。

## 5. 计划与资源

已有本机环境和仓库为实施基础；依赖现有Node、npm、SQLite及已配置模型/Office工具。真实模型和桌面Office是否可用须实际核对，不能当成确定资源。

采用按业务结果划分的小批次；[项目计划](PROJECT_PLAN.md)给出顺序、依赖与出口。目前没有经确认的工时估算、截止承诺、预算或投入人数，相关值保持“未设定”。收到明确交付期后再估算并记录假设、资源和风险。

## 6. 变更与沟通

新任务首先对应已有PR/GOV编号，必要时新增，明确范围和验证。需求变化同时更新当前需求、受影响的验收条件与队列；历史证据保留原结论。

沟通聚焦重大决定、阻碍和交付。交付提供实际成果、验证范围和未完成事项，不使用“功能存在”代替“用户已验收”。运行反馈回到同一任务队列，重复问题可重开并保留证据。

## 7. 阶段完成与项目移交

某批次满足适用需求、相关验证、数据保护、知识同步，并将剩余项明确移交，才可完成该批次。发布、真实业务验收分别记录；项目整体仍持续迭代，不虚构终验签字。

停用或迁移时先安排数据及文件导出、外部原件定位、版本和恢复验证，用户确认可取回后再按授权处理删除。
